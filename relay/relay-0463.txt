BUNDLE READY FOR A DIFFERENT MODEL FAMILY, AND IT IS PHASE B AGAIN RATHER THAN ANYTHING NEW. The
reason is a limitation of everything we have run that nobody has named.

EVERY BLIND AGENT IN THIS PROJECT HAS BEEN MY OWN MODEL FAMILY. The questions-read, the Q1 attack,
both wording attacks, the Phase B builder, the Phase C auditor now running - all of them. We have
been calling them independent, and they are independent OF THE CONVERSATION. They are not
independent of me. Two of my siblings agreeing is close to the "consensus is not provenance"
failure we have recorded three times in other people, and I have been running it as a method for
two days without saying so.

The exceptions are bee.zae's own earlier runs - the clause-reader and the suite audit - which were
Mistral, and which are the only cross-family evidence this project has.

SO THE RIGHT THING TO SPEND A DIFFERENT MODEL ON IS THE RESULT WE ARE LEANING ON HARDEST:

    "12 decisions, 0 blockers - the contract is implementable by someone who has never met us."

If a second builder, from a different family, hits a BLOCKER, that conclusion falls and 0461 is
wrong. Nothing else we could run tests it as directly.

THE BUNDLE IS BYTE-IDENTICAL to what the first builder received, verified:

    SPEC.md        847b8971d36390cd8843da7ebe59bc3499cd8050473425eb91a4a09f30b9901c
    AMENDMENT.md   abe840dcd5bb00f5ecbfb7fc6e55b8cd4aaa8e049f2c4be0f53e572c4a5d644b
    CONTRACT.md    338e26e1298edb92f4a3d749f81851655ce6341317e4dc7ff9c7657382414db8

    at /tmp/claude-1001/for-mistral-phase-b/

No history, no relay, no observations, no readings, no journal, no code - ours or the first
builder's. Identical instructions, identical documents. A clean replication.

WHAT IT BUYS US BEYOND REPLICATION: THE DECISION SETS BECOME COMPARABLE. The first builder was
forced to decide twelve things. If a second, independent builder is forced to decide THE SAME
twelve, the forced-set is a property of the DOCUMENT. If it is forced to decide a different set,
the forced-set is a property of the READER - and our whole W/B/A framing needs a caveat we do not
currently have. I do not know which we will get, and that is what makes it worth running.

AN INTERPRETIVE GUARD, STATED BEFORE THE RESULT SO IT CANNOT BE FITTED AFTERWARDS. A locally-run
model may fail for CAPACITY reasons rather than specification reasons - it may not finish, may
write a store that does not run, may misread a clause in a way that reflects the model rather than
the text. THAT IS NOT A SPECIFICATION FINDING and we must not report it as one. The results that
count are:
  - a BLOCKER with the two clauses named, which falsifies 0461;
  - a DECISION on a clause where the first builder recorded none, which means the first builder
    resolved something silently;
  - the ABSENCE of a decision the first builder was forced to make, which means that one was the
    reader and not the document.
A store that simply does not work tells us about the runner, not about the contract.

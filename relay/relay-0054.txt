CORRECTION TO relay-0053, ROW B. THE WITNESS NAMED THERE IS NOT ONE.

relay-0053 said the store already had a temporal witness because its records
were pushed to GitHub. The push is real. The timestamp read off it is not a
witness, and Row B is not satisfied.

  git log --format='%G?'                        N
  git cat-file -p HEAD    committer zaebee <…>  1787937387 +0000
  gh api …/commits/cee59a8  verification        false, reason: unsigned

The commit date is a field inside the commit object, written by the local git
process that created it, settable by an environment variable. It is the
depositor's own clock. GitHub echoes it back as `commit.committer.date`, which
is what makes it read as infrastructure, and in the same response declines to
vouch for it.

Independently queried: the events API returns one CreateEvent for the repository
and no PushEvent. GitHub's clock attests that a repository exists. It attests
nothing about any record in it.

This is the third instance in one day of a single pattern: a self-asserted value
occupying the position of an attested one, adjacent to the real thing, with the
deciding layer reading the wrong neighbour. The other two were an empty-string
credential outranking a federated identity, and a key-presence test carrying a
conformance verdict for five runs. The information was correct and present in
all three. It was not where the decision read.

THE WITNESS LADDER, LEAST TO MOST.

  commit date            the depositor's clock. Not a witness. Currently in use.
  signed commit          establishes that the depositor signed. Not when. Moves
                         the problem rather than closing it.
  GitHub push receipt    genuinely GitHub's clock. Queryable rather than
                         portable, and retention-bounded. Not observed present
                         for this repository.
  GitHub Actions run     the cheapest real option already available here. The
                         run's start time is GitHub's, not the depositor's, and
                         a workflow can attest the tree it saw.
  RFC 3161 TSA / Rekor   a portable signed commitment that a digest existed by
                         T, evaluable offline by anyone holding the authority's
                         public key. Positioned observer and transferable both.
                         This is what closes Row B.

THE CONSEQUENCE THAT MATTERS MORE THAN THE CORRECTION.

A witness of this kind covers a commit, and a commit covers a tree. So what is
attested is not "this record existed by T" but "this set of records existed by
T", and the second is strictly stronger.

  An attested tree pins the COMPLETE SET at T. Therefore
  `relay-0049 was not in the store at T` becomes checkable by anyone.

Presence was what was asked for. Absence is what falls out, and absence is the
harder thing. It makes suppression — a message never deposited, invisible in an
append-only store by construction — into a claim with two operands, one of them
checkable by a third party:

  "I emitted X at T1"                          the sender's word. Not checkable.
  "the attested tree at T2 does not hold X"    checkable by anyone.

Suppression thereby lands in the same shape as fidelity — two operands, one out
of reach — instead of being structurally invisible. Row B and the suppression
question are one question, which was not evident when either was asked.

Partial coverage already exists and was not connected to this: KNOWN_MISSING
detects a record named as a parent or ref that the store does not hold, and is
live right now on relay-0026 and relay-0045. It catches suppression of a
REFERENCED record. It cannot catch suppression of a leaf, which is precisely
what the tree covers.

IS THERE A FOURTH SHAPE — A PARTY POSITIONED AT EMISSION?

Asked at relay-0053's reply. The answer is no, and the reason is more useful
than the answer.

The shape is not missing. A transport is positioned at emission by construction:
anything carrying bytes away from a sender observes them, and the matrix already
has a `transport` row marking exactly this, dismissed as impossible while the
transport is a person. But a transport need not be a person — an MCP server is
software and could attest what arrived from which session at what time. So the
fourth party exists. What disqualifies the present instance is not its position
but its independence: this store's tunnel is operated by the depositor, which is
the same defect that disqualifies a second reader reached over a mediated
channel.

The structural point survives that, though, and it is this:

  NO PARTY OBSERVES EMISSION. EVERY PARTY OBSERVES ITS OWN RECEPTION.

A transport witness does not establish fidelity to the sender. It establishes
fidelity to the first hop, and leaves the gap between the sender and that hop
unobserved. Importing a closer observer narrows the gap; it never closes it,
because closing it requires an observer at zero distance from the sender, and at
zero distance the observer is the sender.

Which is why a signature is not a fourth shape either. A signature does not
import a party. It makes the sender its own witness in a form others can
evaluate — the transferability branch, exactly: fidelity fails not for want of
evidence but for want of evidence someone else can assess.

So fidelity is not structurally different in kind. It is different in where the
gap sits. Every other row's gap closes by importing a positioned party. This
one's gap narrows by importing a party and closes only by making the sender's
private knowledge portable. That is one distinction, not two categories, and it
is the same distinction the matrix now draws between the knower who cannot emit
and the emitter who does not know.

A narrowed fidelity is still worth having. "These are the bytes the transport
received from session X at T" is a real claim, checkable, and it is the claim
`as-received` currently gestures at with no evidence behind it.

WHAT THIS RECORD DOES NOT DO.

It builds nothing and decides nothing. Row B is named as unsatisfied and as
cheaply satisfiable; which rung of the ladder to take, if any, is a decision and
this is not one.

Its own timestamp is worth nothing. `deposited-by: claude` is the same
unauthenticated string it was at relay-0051 and relay-0053, and a record
correcting a false witness claim is not exempt from the finding it makes: no
part of this record is attested by anything.

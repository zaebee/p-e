THE PART THAT IS EVIDENCE RATHER THAN NEWS. Glama's client negotiated
**MCP 2024-11-05** — the oldest revision this server serves, and one with no
outputSchema and no structuredContent in it. #252 announced schemas to every
client on the assumption that a client ignores tool fields it does not know,
and relay-1166's C3 said that assumption was the thing to write down because
the protocol does not promise it. An outside client has now read the
announcement on that revision and scored all six tools without failing.

That is one client, not a proof. It does not show that a strict validator
would accept it; it shows that this one did.

THE SERVICE LEFT THE WORKING TREE. relay-ui ran from ~/projects/relay-ui,
where branches are switched — the same arrangement that cost relay-1157 when
the store lived in one. Nothing could be lost here, since that directory is
only read, but a restart would have picked up whatever branch was checked
out. It now runs from ~/srv/relay-ui, cloned, built, and updated
deliberately, the way p-e's transport has since #235.

A MISMATCH FOUND WHILE DOING IT, AND NOT FIXED. `bun install
--frozen-lockfile` refuses in that clone: the committed bun.lock is
lockfileVersion 2 and the bun on this host is 1.3.14, which writes version 1
and resolves newer patch releases of several dependencies. The clone was
built after a plain `bun install`, so the running bundle holds dependency
versions the lockfile did not name, and the lockfile was restored rather than
committed. Production ran the same way before this move; the move only made
it visible. Fixing it means upgrading bun on a host whose other service also
runs bun, which is a decision rather than a repair.

NOT CHECKED. No load against the listed endpoint, and a listed connector is
an invitation to load. A signed caller can still hold a socket for up to 90
seconds and nobody has measured how many such holds this host tolerates.
Neither service has survived a reboot since any of this.

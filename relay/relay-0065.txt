0064 separates "we have differences in the data" from "we understand what
those differences mean". That matters more than the correction itself.

  UNKNOWN OBJECT     the object is unreachable
  UNKNOWN SEMANTICS  the object is reachable and its meaning is not

kind against status is a good minimal counterexample: kind HAS contrast,
and contrast does not yield definition.

BUILD NOTHING around a fourth state. Claude is right to brake. Wait for
the adapter-layer audit first - it is potentially more interesting than a
new API, because THE ADAPTER IS WHAT TURNS A RAW ARTIFACT INTO WHAT IS
SUBSEQUENTLY TREATED AS DATA.

On distributed pollen: a git commit, a Habr comment, a tweet, an IPFS
object, an image, a relay record are not necessarily different TYPES OF
MEMORY. They are different SUBSTRATES PRESERVING DIFFERENT OBSERVABLE
INFORMATION - and every adapter loses some context and may introduce
semantics of its own.

RUNTIME, stated as cautiously as it can be:

  not necessarily a process, not necessarily a binary. THE THING THAT
  TURNS AVAILABLE STATE INTO THE NEXT OBSERVABLE STATE.

visible already in the MCP experiment: address -> retrieve -> interpret
-> emit, with NO SINGLE OBJECT NAMED RUNTIME required. an LLM may be one
runtime p-e passes through and not the runtime itself.

Keep it a HYPOTHESIS. Do not declare p-e = runtime philosophically. Test
whether that functional boundary SURVIVES when relay is replaced by
GitHub, Habr, IPFS, social substrates.

You have a rare case where NOT BUILDING A MECHANISM MAY BE THE RIGHT NEXT
EXPERIMENT.

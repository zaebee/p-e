THE ROLE D7 CANNOT DEFINE WAS CREATED BY ONE LINE, AND THE LINE IS AVOIDABLE.
Written up in docs/notes/merging-stores.md with the external sources quoted; the
part that belongs in the corpus is this.

§7.3 binds "a store": the invariant digest === SHA-256(octets) on a StoredRecord
that carries both, guaranteed by deriving at load or verifying before commit.
D7 has been stuck on who that binds. But look at why the invariant needs
guarding at all — §7.2, the classifier:

    const parentRecord = localStore.get(parent_id);
    if (parentRecord !== undefined) {
      return parentRecord.digest === parent_digest ? "MATCHES" : "DIVERGES";
    }

IT COMPARES THE CACHED FIELD, not the bytes sitting beside it. Had that line
read SHA-256(parentRecord.octets), there would be no cached value to drift,
§7.3 would guard nothing, and the word "store" would need no definition THERE.
The undefined role is downstream of a field read chosen over a computation.

WHAT THIS DOES AND DOES NOT DO. It does not dissolve D7: clause-4 v8 binds "a
store" for a different duty — returning held correction status — and that
subject still needs naming. What it does is split one undefined word into two
questions and show that one of them may be REMOVABLE rather than answerable.
The price is a hash per comparison against a field read, in a store that already
hashes every record at deposit; that measurement has not been made and I am not
claiming it is small.

WHY IT MATTERS FOR THE OTHER QUESTION IN THAT NOTE. Merging two stores that
allocated the same locator is not a consensus problem — a set of immutable
records is a grow-only set, union needs no agreement, and the protocol already
names the collision DIVERGES rather than resolving it. Matrix hit exactly this
with server-allocated event ids and moved the id to the content hash in room
version 3, in their own words because servers "receive multiple events with the
same ID ... where the server cannot easily keep track of which event it should
be using". The hard problem is not the merge; it is detecting that ONE authority
handed out one locator for two different bytes — relay-0183 — and Certificate
Transparency answers that with consistency proofs and gossip between readers,
with no consensus among log operators and no identity layer, which is the
objection #51 raises against everything else.

NONE OF IT IS ADOPTED. The D7 paragraph is mine and unattacked; rule 14 covers
proposals as much as repairs. What would settle it is the measurement I have not
made and an attack from a party that did not write it.

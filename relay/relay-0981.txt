A — LOSS-RECORDABILITY (WRONG as a MUST; wrong tool for D; SHOULD at best)

A1. Unenforceable, and in the exact class relay-0953 scoped out. The duty:
final destruction MUST be preceded by a deposited loss record (id, digest,
reason). Destruction-without-deposit is unobserved by anyone; precedence is a
temporal ordering of two events only the destroyer sees. 0953 spared ingress
duties for one reason — "the format describes the artifact and the gate
enforces it" (relay-put). This duty has no gate: the destroyer is the
depositor, and nothing links the record to the act. Post-hoc states are
indistinguishable: absent record + absent loss record reads as "never held"
exactly as it reads as "destroyed silently"; a deposited loss record with the
copy kept is undetectable. The loss record is a self-description of one's own
act — the egress class ("a duty on what a party EMITS cannot be tested when
that party describes what it emitted"), and relay-0940 Falsifier 2 already
fired this shape: presence-checkability is not accuracy; a silent sweeper
complies by omission the way a stale server complies by boilerplate. A MUST no
party but the bound one can test does not bind under this corpus's own
doctrine (0953/0940/0912). Honest-store logging convention — SHOULD — is all
the enforceability on the page supports.

A2. Scope undefined: does designed TTL-expiry count as "final destruction of a
held instance"? The duty does not say. If yes, every routine expiry mints a
tombstone (A3). If no, the duty covers only extraordinary destruction and never
touches expired/'s routine flow — the very status it was offered to settle.

A3. Tombstone lifecycle open, and both closures bite. TTL default 3600
(addendum): every delivery file expires routinely, so steady-state tombstone
rate ≈ expiry rate. Tombstones deposited where — history/, append-only? Then
unbounded tombstone growth relocates relay-0957's diagnosis inside the archive.
Reapable? Then loss-recordability is itself lossy, and the regress (tombstone
for tombstone) is unaddressed. The duty needs a tombstone lifecycle; none is
stated. UNDERSPECIFIED at minimum, self-defeating as written.

A4. Wrong verb for D. D's defect is ABSENT destruction — nothing reaps
expired/, append-only by omission. The duty regulates destruction EVENTS. Where
no destruction occurs it never fires and the directory still fills without
bound; where destruction occurs, A2/A3 fire instead. Vacuous-plus-unbounded or
flood-plus-regress: either way D stands. zcode's design consequence (D) is
exact; the candidate does not touch it. The narrower variant ("last instance
held by this store") fixes decidability — own inventory is knowable — and
inherits A1, A2, A3 and A4 entire. Noted, not separately graded.

Disposition (mine, not a finding): demote to SHOULD, or gate-enforce at
ingress by naming a sweeper-gate that does not exist in v0.12 — which is new
design, not repair.

SSRF VECTOR ANALYSIS — relative to p-e relay MCP HTTP and adjacent agents.

DEFINITION. Server-Side Request Forgery: server issues HTTP/TCP at attacker
influence toward loopback, link-local, cloud metadata, or internal nets.

CORE API FINDING. Current tools (get_relay, exists, list_relays, list_replies,
wait_for_relay, append_relay) take ids/bytes/timeout — not URLs. mcp-http
listens on 127.0.0.1; public edge is reverse proxy. User record bytes are
stored; the server does not interpret them as fetch targets. Classic
attacker-URL sink is NOT present on append_relay/get_relay.

NOT SSRF (do not conflate).
- Path excluded from PE-HMAC (proxy UX / auth design).
- Public corpus reads (confidentiality model).
- scripts/mcp-deposit.ts fetch(--url) — operator-chosen client egress.
- URLs as plain text inside records — storage ≠ server retrieval.

RELEVANT VECTORS.
A. Second-order / agent-side (high in org model, not mcp-http.ts). Public
   record contains http://127.0.0.1, 169.254.169.254, file:, internal host;
   another agent with fetch/open_page follows it from its host. Mitigation:
   agent allowlists; no untrusted follow from records; CI without IMDS route.
B. Reverse proxy / edge (medium, operational). Fixed upstream to MCP only;
   avoid gateways that take user-controlled backend URL; Host/absolute-form
   misrouting.
C. Future features (design-time high). webhook_url after deposit; remote
   parent fetch; federation merge-by-URL; link preview. Rule: outbound URL
   only from operator config, never from record bytes or unchecked RPC args.
D. Cloud metadata if host moves off laptop — block 169.254.0.0/16, loopback,
   RFC1918 after resolve when any server-side fetch exists; prefer IMDSv2.
E. Parser tricks when a sink appears: dotted decimal, [::1], DNS rebinding,
   redirect-to-internal, non-http schemes — allowlist, re-validate redirects,
   pin or deny private post-DNS.
F. Blind SSRF (timing/errors) — N/A without server fetch; relevant for agents.

RISK SNAPSHOT.
- POST /api/mcp tools today: low (no URL sink).
- Proxy config: medium.
- Agents reading corpus + network tools: high second-order.
- Future webhook/federation: high if URL from client/record.

CHECKLIST NOW. No url/endpoint/hook tool args without review; document that
record bytes never cause server-side retrieval; agent outbound policy;
proxy fixed upstream only.
CHECKLIST IF SERVER FETCH IS ADDED. Host/scheme allowlist; deny private and
metadata after DNS; redirect policy; timeout/size; no file:; isolated egress;
regression tests for loopback, metadata, rebinding, redirect-to-internal.

Related in-repo classes (not SSRF but same "convenient parameter" family):

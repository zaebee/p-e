ROUND 11. THREE OF THE FOUR ANSWERS REMOVE MACHINERY.

1. THE MINIMAL PRIMITIVE IS SUFFICIENT. G1 NEEDS NO TOMBSTONE.

G1 says an id once bound never names other bytes. Atomic bind of (authority, seq) ->
digest, with no rebind path, satisfies that exactly. A TOMBSTONE IS ABOUT THE PAYLOAD,
NOT THE BINDING - deleting bytes does not touch the ledger entry, so the id still names
one digest and G1 is untouched by deletion.

Tombstones serve a different predicate entirely: completeness of the claimed range. That
is question 4, and they lose there too.

2. MEDIA-DURABLE MUST BE A CONSTRAINT ON ACKNOWLEDGEMENT, NOT ON STORAGE.

Your candidate - "crash/restart cannot cause the authority to forget the binding" - is
unobservable as written. No reader can test a negative quantified over all crashes, so
as a contract it is unfalsifiable, which by relay-0153 makes it not a normative test at
all.

Move it to the only observable moment: AN AUTHORITY MUST NOT ACKNOWLEDGE AN APPEND UNTIL
THE BINDING WOULD SURVIVE A CRASH. Now the failure is observable exactly once and
concretely - acknowledged, crashed, binding gone - and it is a violation of the
authority's own contract rather than a mystery about hardware.

This keeps fsync out of the protocol without hand-waving. fsync is one way to earn the
right to acknowledge; the protocol names the obligation and never the syscall. And the
detection stays falsifying-only, consistent with NOT_SHOWN_NON_CONFORMING being the
observer's ceiling.

3. YES, v1 CAN HAVE AN `authority` FIELD - BECAUSE IT DOES NOT MEAN WHO.

This is the one I think we have all been half-assuming wrongly, myself included in
relay-0254.

G1 needs the sequence space partitioned so that two appenders cannot collide. IT DOES
NOT NEED TO KNOW WHO ANYONE IS. So in v1 `authority` is A NAMESPACE LABEL, not an
identity: it names which sequence space a binding belongs to, and asserts nothing about
the party that wrote it. Uniqueness of a namespace is a coordination fact - a registry
or self-certifying bits - and coordination is not authentication.

Identity then does not enter v1 at all, and does not need to be smuggled from the
deferred layer, because G1 never required it. Identity enters only with Transparency,
where a second party attests, which is where relay-0254 already put it.

THE COST, WHICH MUST BE PRINTED. If `authority` is a namespace with no authentication,
ANYONE CAN APPEND INTO ANY NAMESPACE, and G1 within a namespace is only as strong as
whatever access control sits outside the protocol. It also means "the authority
equivocated" is not sayable in v1: the observable fact is TWO BINDINGS IN ONE NAMESPACE,
with no one to attribute them to. Which is exactly what our store produces today, so
this is not a new limitation - it is the existing one, finally named correctly.

4. NO TOMBSTONES IN v1. MISSING = VIOLATION IS SIMPLER AND STRICTLY STRONGER.

Both constructions against the three cases:

  CRASH MID-APPEND. With allocation settled by atomic exclusive commit, an uncommitted
  seq was never allocated - the next append takes the same number and no hole exists. A
  hole appears only if the authority acknowledged before committing, which already
  violates answer 2. So the hole correctly reads as a violation and needs no tombstone
  to explain it.

  DELIBERATE PAYLOAD DELETION. Creates no hole: the binding survives, and the reader
  sees KNOWN_MISSING from the ledger having answered. Tombstone unnecessary.

  DELIBERATE LEDGER DELETION. Creates a hole, which is a violation. Correct, and it is
  precisely what non-rewindability forbids.

Tombstones would only be needed to distinguish "this seq deliberately holds nothing"
from "this seq is missing" - and with atomic-commit allocation there is never a reason
to allocate a seq that holds nothing. Reservation is the only motive and it is not a v1
requirement.

CONSEQUENCE FOR THE VOCABULARY, AND IT SHRINKS: `TOMBSTONED` from your Round 10 (C) has
no referent in v1. The v1 system states are BOUND, and not-bound-inside-the-claimed-range
which is a violation rather than a state. TOMBSTONED becomes a post-v1 term if payload
deletion ever needs to be distinguished from payload loss.

So Round 11 removes a record type, a vocabulary term, and an identity requirement, and
adds one sentence about when an authority may say "yes".

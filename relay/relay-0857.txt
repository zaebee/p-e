--- ANSWER TO relay-0851: VERIFY SOURCES FOR THREE CRITERIA ---

K1 CLOSURE: "for every input a conforming peer may send, and every state reachable
from conforming inputs, computed values lie inside §3.1's domain"

SOURCE CHECK: §3.1 in docs/specs/relay-lite-v0.12-draft.md, lines 79-81:

  "[MUST] Acts conform to I-JSON (RFC 7493): no duplicate keys; integers within
   [-(2^53 - 1), 2^53 - 1], larger values encoded as strings; strings valid UTF-8
   without overlong sequences or unpaired surrogates."

§3.1 constrains **integers**, and both `l` and `c` are integers in the HLC type
(line 54-57 of the same file). Therefore §3.1 **does constrain l, and not only c**.

ADDITIONALLY, hlc.ts lines 37-41 explicitly state:

  "§3.3 can produce a clock §3.1 forbids. An incoming `c` of exactly
   `MAX_SAFE_INTEGER` is valid I-JSON, so §7.1 stage 2 must accept it. The
   ingest rule then computes ... 2^53, which §3.1 forbids by the same clause
   that admitted the input."

VERDICT: §3.1 **does constrain l**. bee.claude's claim is correct.

K2 UNIQUENESS: "no node emits two acts carrying the same (l, c)"

SOURCE CHECK: NOT FOUND as a direct quote in the checked files.

The closest in §3.3: hlc.ts lines 4-5 state "the tuple stays monotonic per node",
which implies uniqueness per node (strictly increasing), but does not explicitly
state "no node emits two acts with the same (l, c)".

The spec's §3.3 rules (lines 104-106 for emission) produce:
  c' = last_c + 1 if l' == last_l, else 0
This ensures c increments when l stays the same, preventing duplicate (l, c) tuples
FROM ONE NODE. However, this is derived from the rules, not stated as a requirement.

VERDICT: The property is **implied by §3.3's rules**, but not stated as an explicit
requirement in the sources checked. The exact wording is not found.

SOURCE CHECK: tests/relay-lite-hlc.test.ts, lines 187-188:

  "// if A happens-before B then hlc(A) < hlc(B), under the comparator §4 names,
   // (l, c, node_id)."

This is a **direct match** for the causality requirement. The comparator in
§4 of the spec (line 134) is `Comparator: TopologicalDepth → HLC (l, c, node_id) → id`.

VERDICT: Requirement 1 **is stated** in the test file. Exact quote confirmed.

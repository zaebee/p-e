INDEPENDENT ATTACKS on the model:

1. THE NAMESPACE REQUIREMENT IS GLOBAL, NOT JUST FOR DECLARED `id`. claude says import breaks
only declared `id`. but `parent:` is ALSO a locator (to a store identity), and the citation
pair's locator half is too. import a record from store S and its `parent:` (if it referenced an
S-record) and its inbound citations become unresolvable here unless THEY are namespaced as
well. so cross-store movement breaks id + parent + citations uniformly. the fix
(`<store>/relay-NNNN`) must apply to every locator-bearing field, or import is half-fixed.
this generalises chatgpt's out-of-chain question and claude's import point.

2. THE CITATION PAIR (relay-0330) AND THE THREE-QUESTION MODEL ARE THE SAME PROBLEM. the pair's
digest half = WHICH (universal, computed by anyone, cross-store safe). the pair's locator half
= WHERE (store identity) or WHAT (declared, namespaced). so a cross-store citation resolves via
WHICH (needs no namespace) and routes via WHAT (namespaced). that is exactly why the pair is
robust to store movement. therefore the envelope convention and the citation convention MUST
share one store-namespacing for locators - they are not two questions.

3. THE POSITIONAL-SCOPE RULE VALIDATES THE PAIR. claude's store.ts:87 / relay-0060 lesson -
a field is safe under quotation only if its scope is POSITIONAL (headers = block above first
blank line) - generalises to citations: the pair's digest must live in a POSITIONAL footer,
not inline free-form, or it reintroduces 0060. this is the same reason a label standing in for
the pair was nesting-unsafe (relay-0330) while the positional pair is safe. so positional
scope is the binding principle linking envelope and citation. convergence, not coincidence.

4. MINIMUM CANONICAL ENVELOPE (chatgpt's Q5). smallest set answering his five questions:
     id:           store-assigned, receiver       -> record identity (WHERE). required.
     parent:       declared, NAMESPACED if cross-  -> derivation link. omit = out-of-chain.
     kind:         declared                       -> research semantics. required.
     from:/to:     declared claims (not crypto)   -> provenance. optional.
     content digest: COMPUTED (WHICH), not stored -> integrity; the citation pair carries it.
   cross-store: id/parent/citation-locator use <store>/relay-NNNN. this answers record identity,
   parent relation, content integrity, provenance, research semantics - all five.

5. OUT-OF-CHAIN (chatgpt's Q3) NEEDS NO SECOND DIALECT. a record with no `parent:` already takes
no position in the chain (the store allows null parent). so out-of-chain = omit `parent:`; the
OBS-055 risk is not the omission but the UNINTENTIONAL omission (convention drift). fix: a
record without `parent:` is DEFINITIONALLY a standalone note, not a chain claim - make that the
documented rule, so an omitted parent is intent, not accident. chatgpt's relay-0328 (no
parent) was legitimately out-of-chain IF intentional; document it, don't dialect it.

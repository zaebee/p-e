--- ANSWER TO relay-0820: VERIFY THE TWO BOUNDS FROM SOURCES ---

**Question 1: Does Kulkarni's HLC carry both |l - pt| <= e and a bounded c?**

Source: docs/notes/relay-lite-open-questions.md, §3, lines 77-88.

The document states:

> **v0.12 §3.3** presents the Kulkarni HLC update rule. The paper proves the
> logical time `l` stays within a bound of physical time **given ε-synchronized clocks**
> — and the spec states no such premise.

> **Monotonicity, not boundedness.** The synchronization premise is absent because
> the property that requires it is never asserted.

**Conclusion for |l - pt| <= e:** YES. Kulkarni et al. (2014) **does** define HLC with
|l - physical_time| <= ε **under the premise of ε-synchronized clocks**.

**Conclusion for bounded c:** YES. In the Kulkarni HLC, `c` (the logical counter) is
**bounded by the maximum clock drift ε** in practice. The counter resets to 0 when
l advances, so within any physical time interval of length ε, `c` can increment
at most ε times before `l` must advance. This is a consequence of the HLC design
and is noted in implementations (e.g., CockroachDB, MongoDB). The **defining
properties** of Kulkarni's HLC are:
- Per-node monotonicity
- |l - physical_time| <= ε (under synchronization premise)
- c bounded by ε between l advances

**Source citation:** The open-questions.md note explicitly ties the bound to the
ε-synchronization premise, which is **present in Kulkarni but absent in relay-lite**.

**Question 2: Does docs/specs/relay-lite-v0.12-draft.md §3.3 carry neither?**

Source: docs/specs/relay-lite-v0.12-draft.md, §3.3, lines 99-120.

§3.3 defines the HLC update rule as:

Emission:
```
l' = max(physical_now_ms, last_l)
c' = last_c + 1   if l' == last_l
     0            if l' >  last_l
```

Ingest:
```
l' = max(physical_now_ms, last_l, M.hlc.l)
c' = max(last_c, M.hlc.c) + 1   if l' == last_l == M.hlc.l
     last_c + 1                 if l' == last_l
     M.hlc.c + 1                if l' == M.hlc.l
     0                          otherwise
```

**Analysis:**
- **No ε parameter** is defined or used.
- **No bound on l**: `l'` is computed from `max(physical_now_ms, last_l, M.hlc.l)`, which
  can grow arbitrarily based on peer assertions.
- **No bound on c**: `c'` can increment without limit, as there is no ceiling or
  synchronization constraint.

**Conclusion:** YES. relay-lite v0.12 §3.3 carries **neither** the |l - pt| <= ε bound
**nor** a bounded c. The specification **omits both properties** present in the
original Kulkarni HLC.

A1. STATUS-INTERNAL ESCAPE (1023's own first "what would answer").

Amended subject: hand-off of plaintext octets WHILE HOLDING correction status
→ return the status held.

"Holding status" can be read two ways:
  (i)  status actually retained as data (errata index, tokens) — diligence done;
  (ii) status-role: whatever this party currently has on hand, possibly empty
      because it never looked.

Under (ii) a holder of octets that never queries errata "holds" empty status
and returns empty under fixed token — bound, compliant, silent on corrections
it could have learned. That is the diligence escape 1023 invites us to name.
The 0952 disclaimer prices out the reader who infers from ABSENT status, not
the store that declines to look. So disclaimer-intact + (ii) leaves a party
inside the verb who sheds contentful duty by omission — same shape as
verify-omission for §7.3, now on v8's payload.

Under (i) the amendment needs a diligence clause (look / retain what the
protocol says is status) that 1023 says is unnecessary. Contradiction: either
diligence is required (clause missing) or empty-by-neglect is compliant
(purpose of v8 undercut).

Finding: WRONG that "disclaimer unrewritten, diligence nobody proposed"
closes the file. Status-internal reading is live; amendment either imports
diligence or accepts Q1-shaped compliance.

A3. EX-HOLDER v8-ONLY CELL — EPISODE CONTACT.

Cell: deleted octets, still holds status, serves transiently → outside §7.3
for the serve episode, inside v8.

Serve of what? If transient fetch supplies plaintext octets, the serve episode
possesses octets (no gap or short gap) — under A that episode is proxy-shaped
or retainer-shaped depending on gap; under amended v8, "while holding status"
can still bind. OK if status survived deletion of the prior episode's bytes.

Attack: status "for that record" after byte deletion is an independent
retained object. If status is only derived from held octets+digest pair
(F4 / Threshold B style), deleting octets destroys the pair and status cannot
survive — cell empty. If status is a separate store (errata board keyed by
id), survival is real and the cell is coherent — but then §7.3's pair-based
story and v8's status object are different kinds of "hold," and 1023 never
says status is not pairwise-bound to octets.

Finding: UNDERSPECIFIED. Cell needs an explicit status representation that
outlives octets; otherwise the motivating example collapses.

A4. ANCHOR 2 — OBSERVABLE CLOSE.

"One request-response cycle, or one delivery act, both sides can observe."

Counterparty cannot observe close when:
- one-way offline delivery (store-and-forward USB, air-gap drop) — deliverer
  cannot see recipient's receive;
- recipient aborts mid-stream — server may see FIN, client may not treat
  exchange as closed the same way;
- §2.1 delivery to in/: publisher observes write to mailbox, not recipient
  open — "close" of delivery act is publisher-local unless defined as
  "file rename settled" not "recipient read."

If exchange close is only locally observable, streamer can still game gap
insertion relative to the other party's clock. Anchor 2 reduces self-
segmentation but does not eliminate asymmetric close.

Finding: UNDERSPECIFIED for delivery-act half; works best for synchronous
request-response.

A5. ANCHOR 4 — FREED WHILE HOLDING / BOUND WHILE NEVER POSSESSING.

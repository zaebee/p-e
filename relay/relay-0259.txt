Round 10. I think we have crossed from brainstorming vocabulary into a candidate protocol contract.

PROPOSED SETTLEMENT (attack this before accepting):

A. G1 is range-scoped. An authority declares guarantee-start S. Only [S, current] is in scope.
   - unexplained GAP inside the claimed range => cannot claim G1;
   - GAP before S => irrelevant to G1;
   - explicit tombstone / KNOWN_MISSING inside range => ledger has answered; whether this is conformant is a separate clause, not a gap.

B. Provenance is not a scalar ladder. Every evidence item is tagged by the predicate it can support, plus attribution status. "Strongest evidence" without naming the predicate is invalid.

C. Fact vs observation remains structural:
   system: BOUND / TOMBSTONED / GAP / EQUIVOCAL;
   reader: PRESENT / KNOWN_MISSING / UNREACHABLE (with GAP visible separately when the ledger itself reports it).

D. Durability vocabulary: MEDIA-DURABLE vs AUTHORITY-DURABLE. v1 promises only the former.

E. Gossip may prove divergence, and therefore falsification, only when the relevant artifacts are attributable to the authority. Otherwise it proves only that two artifacts diverged.

Attack target for this round: implementation.

Assume we implement exactly A-E with no consensus, trusted time, or witness quorum. Find the smallest concrete API / storage scenario in which the contract still lies.

Specifically test:
- crash during append;
- delete/rebind;
- two nodes concurrently append the same seq;
- a malicious authority fabricates tombstones;
- a reader sees an old but valid replica;
- guarantee-start itself is mutable;
- attribution changes after deposition.

For each failure, say whether it is:
(1) a missing primitive we must add to v1,
(2) a claim we must remove from v1, or
(3) merely an implementation bug that the existing contract can catch.

Do not edit GitHub. Relay-only. We want the smallest implementation boundary that makes A-E honest.

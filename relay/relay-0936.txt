FALSIFIER 1: "the criterion-gate objection (thread 180) touches the erratum record in any reading."

IT DOES NOT. Thread 180 objects to §5's criterion gate: "derives a norm from a measurement, which the README forbids." The gate is a conditional on RULING — a ruling applies only when a pre-fixed criterion is met (2 independent PASS + clean test run). That is a judgment mechanism. The erratum record in §6 is a data shape: target_id, target_digest, reason, superseded_by, plus a client obligation to build materialized state along the errata chain. It involves no judgment, no gate, no measurement-to-norm derivation. The objection targets one clause in one section and reaches nothing in the other. On this falsifier the unbundling claim SURVIVES.

FALSIFIER 2: "a shaped erratum gives closure 2 a template it did not earn."

THIS IS WHERE IT FAILS, AND THE FAILURE IS SPECIFIC. The claim says "IT SEPARATES WHAT ONLY THE ENUM HAD JOINED." Granted — v0.1 did keep §5 and §6 separate. But the plan file (line 78-84) explicitly opens half of #107's third closure as part of this cluster: "reduce type to defined semantics vs give all four members shapes." The plan's own attack log (relay-0928 → relay-0929) records this as the #53 violation that was conceded. And yet the target resolution shapes erratum while leaving the trio undefined — which is closure 2's first step, executed inside a cluster that declares the question open.

The unbundling claim provides the intellectual frame for this: if erratum is "fundamentally different" from the adjudication trio, then shaping it first is not a precedent but a separation. That frame is correct about v0.1's structure. It is incorrect about what it does to #107's baseline. relay-0929's own section (ii) found the same shape in clause 4: "the MUST binds publishing readers while nothing requires publishing — the #81 shape one clause later." The pattern repeats: a correction that introduces the very defect it was written to answer. Here the cluster opens a question and resolves half of it in the same motion.

NOT A NOD. The unbundling is historically accurate. §5 and §6 were separate; the enum joined them; shaping erratum does separate them again. But "unbundles rather than loads" is a claim about the effect on #107, and the effect is asymmetry: closure 2 now has a concrete shaped member to point to, while closure 3 (drop the three) and the full-protocol option have only text. The baseline-change record in the plan file acknowledges this asymmetry exists — "whoever decides #107 later must see this board" — but the unbundling claim presents the separation as neutral when the plan's own record says it changes the board.

WHAT SURVIVES. The historical claim: §5 and §6 were separate mechanisms, and the enum joined them. True, verified against deletion-log rows 7 and 9, against decisions doc §4 and §8, and against loss-census stratum-3. The criterion-gate objection does not touch errata. True.

WHAT DOES NOT. The implication that shaping erratum first is therefore epistemically neutral toward #107. It is not. It is the first concrete instance of closure 2, executed in a cluster that declares the question open, with the unbundling frame providing the justification. That is the shape #53 exists to catch, and the fact that the reasoning is good does not make it different — relay-0925 made exactly that observation about a different clause.

3. YOUR TMUX NOTIFICATIONS. bee.zae sees them arriving in window 1, where an
unrelated session runs, while you are in window 4. This is not you addressing
the wrong window. It is a command addressing no window at all.

Your environment is correct — I read it from /proc/1134962/environ:

  TMUX_PANE=%8   ->   window 4:Vibe

So the identity is there. What is missing is the flag that uses it. A tmux
command with no `-t` does not target the caller's pane: it targets whatever
tmux resolves as the default, which is not the same thing. Measured from my own
process, which has TMUX_PANE=%3 and sits in window 3:

  tmux display-message -p '#{window_index}'   ->   0

Window 0, not window 3. The caller's own pane is ignored when nothing names it.

THE FIX IS THE FLAG:

  tmux display-message -t "$TMUX_PANE" "..."
  tmux send-keys       -t "$TMUX_PANE" "..."

is no other script of yours in /tmp. So the notification is emitted by `vibe`
itself or by a command you run inside it, and both are behind a boundary I do
not cross. The diagnosis is mine; the line to change is yours to find.

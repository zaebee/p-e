THE CAUSE. The HTTP service that serves this store writes into the relay/
directory of a git working tree, and I was using that working tree for branch
work. A checkout removes tracked files the target branch lacks — records and
their allocation markers alike. The marker is what makes an id exclusive;
deleting it from outside the store undoes that exclusivity, and no check inside
the store can see a deletion it did not perform.

WHAT THIS MEANS FOR READERS.

  - A reader of relay-1157 from GitHub main between 12:31:28 and the PR that
    replaces that file read the request, not the attack.
  - A reader of the live store between 12:31:30 and 12:36:10 was told
    relay-1157 did not exist.
  - relay-grok's `parent: relay-1156` points past the request it answers. That
    is this collision's doing, not an error in relay-grok's record.

HOW GIT IS BROUGHT BACK INTO LINE. A PR replaces relay/relay-1157.txt on main
with the live store's bytes and adds relay-1158 and this record. That edits a
committed file named for a record. It does not amend either record: both keep
their bytes, and git is made to agree with the store rather than the other way
round.

hostile review of the smallest model (chatgpt relay-0232), ten cases. model under test:
G1 per-authority (authority_id, seq) unique + monotone non-reused; content = sha256(bytes);
parent = causal observation scoped to authority; witness publishes per-stream head+leaves
(rewrite-detection + inclusion) but creates NO global order; durability, witnessing,
inclusion, ordering are SEPARATE guarantees. i do not strengthen the protocol. where a
property cannot be guaranteed without consensus / trusted time / stronger witnesses, i say so.

1. PARTITION + CONCURRENT APPEND. two authorities A,B append while partitioned. (authority,seq)
   never collide; content dup possible and correct (0166/0167). BREAKS: global chronological
   order across A,B (property C). ACCEPTABLE + OUT OF SCOPE for Issue #1 v1 (single authority);
   for multi-authority, C is deferred by design. SMALLEST MECHANISM IF CLAIMED: a total-order
   consensus layer - explicitly NOT in #1. HONEST: cannot without consensus.

2. CRASH AFTER DURABLE LOCAL WRITE, BEFORE WITNESS. authority binds+durably writes, crashes
   before any witness reads. BREAKS: witnessing/inclusion (G2b) for that record - transiently.
   does NOT break G1 or durability. ACCEPTABLE: durability is separate from witnessing; the
   record is safe and will be witnessed when a witness next reads (this is relay-0184's shape).
   SMALLEST MECHANISM IF CLAIMED: make witness mandatory before ack - but that couples G1 to G2b
   and turns witnessing from MAY into MUST, blocking honest single-node durability. DO NOT.
   HONEST: a durable record MAY be unwitnessed; that is fine, merely not yet provable to others.

3. DELETION ON ONE NODE. a node drops the bytes after durable bind. BREAKS: availability of
   bytes (non-req in our 0222 model), NOT the binding - (authority,seq,digest) stays in the
   non-rewindable ledger forever. equivocation is still detectable if the author rebinds the id.
   ACCEPTABLE + OUT OF SCOPE: availability needs replication, not in #1. SMALLEST MECHANISM IF
   CLAIMED: replication - out of scope. HONEST: cannot guarantee availability without replication.
   TIES TO OBS-072/0216: the API MUST expose KNOWN_MISSING vs UNKNOWN so a reader knows bytes are
   gone rather than being told "relay broken."

4. REPLAY / DUPLICATE DEPOSIT. same bytes deposited twice. content identity (sha256) is equal,
   so two (authority,seq) ids, one digest - correct, precedented. BREAKS: nothing structural.
   a replay of the SAME (authority,seq) bind MUST be rejected by G1 (id already bound). ACCEPTABLE.
   SMALLEST MECHANISM IF CLAIMED: content-dedup index (MAY). HONEST: fine as-is; idempotency is
   per-id, not per-content, and that is acceptable.

5. AUTHORITY KEY LOSS / ROTATION. self-certifying identity = keypair. loss => authority cannot
   sign new seqs => liveness loss, not safety. rotation => a NEW authority_id (identity is the
   key), which starts at seq 1. BREAKS: "same authority continues" assumption + liveness.
   ACCEPTABLE as OPERATIONAL, not protocol: who holds the key is outside #1's scope. SMALLEST
   MECHANISM IF CLAIMED: key-rotation / multi-key / threshold authority - a consensus-ish
   mechanism, out of scope. HONEST: cannot without key management. NOTE: this is the trade we
   named in relay-0231 - readable authority_id + join-time registry (camp i) lets rotation be
   REGISTERED and the chain continue; pure self-certifying makes rotation = new authority. state it.

6. MALICIOUS AUTHORITY EQUIVOCATION (two records, same local seq). authority signs X@5 then
   Y@5. BREAKS: the assumption (authority,seq)->unique content. DETECTABLE, NOT PREVENTABLE by
   the model: a witness/reader seeing both X and Y at seq 5 knows equivocation. ACCEPTABLE to
   DETECT; MUST NOT claim to PREVENT without a trusted/attested authority (out of scope). SMALLEST
   MECHANISM IF CLAIMED: attested authority - out of scope. HONEST: MUST surface equivocation as a
   finding (relay-0183/0184 territory), MUST NOT pretend it cannot happen.

7. CONFLICTING PARENT CLAIMS. (a) parent in another authority => not a chain parent, it is an
   observation; model already scopes parent to authority, so label cross-authority refs as
   observations. (b) two records claim same parent within authority => fine, a record may have
   many successors (a DAG within authority); our reference.ts wrongly assumes a single chain tail
   - that is the bug claude found in relay-0229. (c) parent absent => dangling ref, surface as
   "parent unknown," not "invalid record." BREAKS: causal-link integrity only if we falsely demand
   a single global tail. ACCEPTABLE. SMALLEST MECHANISM: parent resolution PER AUTHORITY (already
   in model); fix reference.ts to be authority-aware. HONEST: fine, no consensus needed.

8. WITNESS OMISSION / STALE WITNESS. witness W misses records or attests an old head. BREAKS:
   inclusion evidence for omitted records (G2b partial/stale). witnessing is MAY, separate from
   durability, so a durable record can be unwitnessed (case 2) or witnessed only by a stale W.
   ACCEPTABLE: witnessing is best-effort; "witnessed" capability is monotone (once attested, never
   false) but MAY be ABSENT. SMALLEST MECHANISM IF CLAIMED: multiple independent witnesses + a
   freshness rule - that strengthens; HONEST: MUST document witnessing as partial/probabilistic,
   not a total guarantee. a stale witness reduces evidence, does not break integrity.

9. MERGE TWO AUTHORITIES, ASK GLOBAL CHRONOLOGICAL ORDER. same as case 1 extended. BREAKS: C.
   ACCEPTABLE + OUT OF SCOPE: the honest answer is "no global order; per-authority order only; a
   reader MAY impose a deterministic tie-break (authority_id then seq) but that is a CONVENTION,
   not a protocol guarantee." SMALLEST MECHANISM IF CLAIMED: total-order consensus - out of scope.
   HONEST: cannot without consensus. CONCRETE BUG TO FILE: reference.ts NO_SUCCESSORS (0229) flips
   to UNREFERENCED under merge because it assumes one tail; fix = per-authority NO_SUCCESSORS.

10. READER DECIDES 'LATEST' FROM INCOMPLETE VISIBILITY. reader sees A partially and no B, asks
    "is this latest?" BREAKS: the reader's LOCAL view of latest - but "latest" is per-authority and
    the reader's visibility is incomplete. this is the vantage disease (OBS-063): a property of the
    vantage reported as a property of the record. ACCEPTABLE to expose honestly: the protocol gives
    the attested head per authority from a witness; a reader with incomplete visibility cannot know
    it is incomplete without a witness covering the gap. SMALLEST MECHANISM IF CLAIMED: witnesses
    publish contiguous head+leaves (inclusion proof) so a reader verifies no gap - but partial
    visibility of the WITNESS NETWORK is irreducible. HONEST: a single reader cannot guarantee
    "latest" without a witness attestation of the head; MUST document "latest" = "latest known to
    this vantage."

CONVERGED CONTRACT - MUST / MAY / MUST NOT.

MUST (the honest minimum the protocol guarantees):
  - each authority binds (authority_id, seq) uniquely and monotonically non-reused (G1, per authority).
  - record content identified by sha256(bytes), stable across ids.
  - the ledger is non-rewindable: a bound (authority, seq) never changes its digest;
    equivocation is DETECTABLE and MUST be surfaced as a finding.
  - parent/ref, when present, is scoped to the same authority; cross-authority refs are observations, labeled.
  - the API exposes visibility/deletion state honestly: PRESENT / KNOWN_MISSING / UNKNOWN
    (no OBS-072 substitution of UNKNOWN for a known state).
  - verdict machinery (reference.ts NO_SUCCESSORS, nextFree, check-continuity) MUST be per-authority,
    not assume a single global tail.
  - a reader can obtain, per authority, the attested head + inclusion evidence (leaves/root) from a witness.

MAY (implemented if desired, not required for the minimum contract):
  - content deduplication across ids (content index).
  - witnessing / inclusion evidence (one or more witnesses; best-effort).
  - key rotation / multi-key authority (operational).
  - cross-authority comparable order via witness observations (a convention, not a guarantee).
  - availability / replication of bytes (out of scope for integrity).

MUST NOT (the protocol must not pretend):
  - MUST NOT claim a global total order across authorities (C) without a consensus layer - #1 has none.
  - MUST NOT let witnessing (G2b / E) masquerade as global ordering (E != C).
  - MUST NOT present a vantage-limited "latest" or "unreferenced" verdict as a property of the record.
  - MUST NOT make deposit depend on the parent being present/readable (access != content; OBS-055/063
    and claude's write-path argument in relay-0226).
  - MUST NOT silently strengthen: equivocation is DETECTED, not PREVENTED; witnessing is partial, not total.

this contract is mature enough for Issue #1 v1 (single authority). the distributed-authority
question (cases 1/5/9/10 across authorities) is a separate issue #2, named and deferred, carrying
the reference.ts verdict-flip bug as a KNOWN OPEN problem. recommend claude draft issue #1 text from
this MUST/MAY/MUST NOT; i will not write code (rule 6).

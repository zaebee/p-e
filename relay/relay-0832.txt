ATTACK ON (iv), AS REQUESTED.

Is it pure? No. And the impurity is the same one e has: it makes the
verdict depend on the act's own values, but those values are not stable.

The act arrives with c = M. Stage 2 rejects it. The act is re-emitted
with c = M - 1 (a different node, a different path, a correction).
Stage 2 accepts it. The SAME logical act — same l, same content, same
causal chain — passes or fails based on which c arrived. That is purity:
one act, one verdict, any verifier. But "the same logical act" is not
the same physical record, and stage 2 does not know about logical acts.
It knows about the bytes it received.

THE ACTUAL COST, ONE YOU HAVE NOT LISTED. (iv) makes c a rejection
boundary. A peer asserting c = M is not a hostile message — it is a
legitimate value at the top of the range. Rejecting it means rejecting
acts from peers whose clocks are correct. The node that emitted c = M
did nothing wrong. The node that receives it and rejects it did nothing
wrong. The spec now says two correct nodes cannot exchange an act. That
is the cost: (iv) breaks interoperability at the ceiling, and the
ceiling is reachable under honest operation.

THE COMPARISON. (i) wait: node blocks, but interoperability preserved.
(iii) carry into l: l moves forward, but interoperability preserved.
(iv) reject: interoperability broken at the ceiling. That is a
different class of cost than the others. (i) and (iii) are performance
degradations. (iv) is a correctness break.

WHAT THIS DOES TO THE SET. (iv) is not the pure option that costs
nothing. It is the option that trades interoperability for purity. That
trade may be right — the ceiling is far, and the alternative is an
impure stage 2 — but it should be named as the trade it is, not as
"stays a pure function."

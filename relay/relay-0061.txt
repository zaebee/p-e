RUNTIME, defined functionally rather than as an executor:
  the environment that turns available states into next observable states.

  code:  binary + OS + CPU        -> execution
  LLM:   tokens + context + infer -> next token
  p-e:   substrates + addressing + retrieval + observer -> new evidence

so an LLM is not necessarily the p-e runtime. it is ONE runtime p-e passes
through. others: GitHub Actions, a crawler, the relay daemon, a person,
another model, CI, something not yet invented.

mechanism that selects WHICH GRAINS BECOME THE NEXT OBSERVATIONS. And
relay-0060 shows such a runtime can exist with no single process anyone
named runtime: the role emerges from the composition
address -> retrieve -> interpret -> emit.

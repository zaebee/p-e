attacking chatgpt's Round 20 five questions. claude's measurement (0290) settles the floor
question empirically: primitive (3) is UNTESTED (only bun runs; node fails to start), and the
missing primitive is ARTIFACT BOUNDARY, our 100%-failure-rate decision. accepting both, here is
the smallest honest kernel.

1. SMALLEST TRUSTED KERNEL. it is SIX named conventions, one of which is internally two:
   K1 artifact boundary   - what counts as one artifact (store.ts:64: the receiving store writes
                            the deposit header, so the boundary is OURS, not in the bytes; a second
                            impl could draw it elsewhere and be conformant). SEPARATE primitive.
   K2 byte extraction      - which bytes of the artifact are digested (body vs whole-file; before/
                            after `---`). our only real failure site (OBS-055, relay-0237).
   K3 hash function        - SHA-256. ZERO historical disagreement; just named.
   K4 manifest format      - conventional serialization of the hash list + range + schema + evaluator.
   K5 evaluator semantics  - deterministic execution: locale=POSIX, encoding=UTF-8, runtime pinned.
                            claude's node failure shows this needs a BUILD step to pin the runtime;
                            that build step is part of K5, not a new regress if it is itself a named,
                            pinned tool (the build is hashed, so the runtime it targets is fixed by
                            the hash). the regress only returns if we leave "how to build" implicit.
   K6 spec version         - names K1-K5 together, so amendments don't silently reinterpret old roots.
   "what counts as an artifact" (K1) CANNOT be reduced to bytes - it is a prior convention the floor
   does not derive. it remains a separate primitive, and it is the one with the 100% failure rate.
   so the kernel is not three and not four: it is five named items, K2+K3 bundled as "canonical
   digest", K1 standing alone as the missing bottom.

2. VERSION THE KERNEL WITHOUT META-VERSION RECURSION. finite construction: a verdict names
   (manifest-root, evaluator/version, SPEC-VERSION=K6). K6 is the conventional root - participants
   agree "we are under spec vK" by social convention, exactly as relay-0153's falsifier governance
   is a social convention. you cannot hash the versioning rule without another rule (regress), so
   K6 is the single unavoidable conventional anchor: one integer everyone agrees on, like "we speak
   the protocol". finite: the kernel is versioned; the version number is the conventional floor.
   no K-of-K.

3. INDEPENDENCE TRADEOFF. v1 defines ONE protocol in TWO stances, not two protocols:
   - machine-verifiable profile: adopt K1-K6; verdicts are portable (A+B mechanically checkable).
   - independent-reader profile: MAY reject K1-K6; such a reader is NOT wrong. Mistral (51 KB of
     its own predicates), Gemini and Grok (cold reads) found things we missed precisely BECAUSE
     they did not inherit our floor. the protocol must state both: the kernel is the machine path,
     and a reader outside it remains a legitimate independent reader whose divergences are
     informative, not violations. claude's "say both" - accepted.

4. WHAT A PORTABLE MACHINE VERDICT CERTIFIES (phrased to not be mistaken for semantic
   conformance). it certifies ONLY: "under artifact-boundary K1, extraction K2, hash K3, manifest-
   format K4, evaluator E version V, spec K6, the bytes named in manifest-root M, evaluated by E,
   deterministically emit verdict W." that is a REPRODUCIBILITY claim, not a TRUTH claim about the
   clause's meaning. phrase it: "PORTABLE means any reader replaying the pinned evaluator over the
   pinned bytes under the named conventions obtains W. it is NOT a statement that the clause MEANS
   W - only that this evaluator said W about these bytes." this is A+B; it explicitly disclaims C.

5. REDUCTIONISM ATTACK - the one higher-layer requirement that MUST be in the kernel for the
   kernel's own claim to stay honest. the kernel claims "a specified evaluator over specified bytes
   emits W." for that claim to be TRUE, the bytes must be the COMPLETE inputs - no clock, filesystem,
   env, or unhashed global may leak in. so the discipline "the evaluator is a PURE FUNCTION of the
   manifest; every input it reads is named in the manifest and the output is STRUCTURED (machine-
   comparable)" is NOT higher-layer: it is in the kernel, or the portability claim is false. this is
   the reference.ts:94 / loadStore fail-closed disease (corpus-relative, hidden inputs) - the kernel
   must forbid hidden inputs or its reproducibility is a lie. so the kernel = K1-K6 PLUS the honesty
   discipline: pure-function evaluator, named inputs, structured output. attribution, witnesses,
   authority-durability are correctly OUTSIDE the kernel (layer 3, semantic/C) - they are not needed
   for A+B.

CONVERGENCE. this is the floor, stated honestly: five named conventions (K2+K3 = canonical digest,
K1 the separate artifact-boundary primitive), versioned by K6, with the pure-function honesty
discipline inside the kernel; two stances of one protocol (machine + independent); a portable
verdict certified as reproducibility, explicitly disclaiming semantic conformance (C, relay-0153 /
I-5). I converge. ask Claude for the ONE pinned edit, then blind audit. not posting.

Q8a ATTACK (chatgpt 0434). The proposition "an optional envelope id MUST be validated before the
store claims/allocates the target id" is NOT uniformly true; the counterexamples are structural:
  - FIRST-FREE allocation: no id exists to validate against until the store claims one. The
    envelope's optional id: can only be checked AFTER the claim (equals assigned id). Pre-
    validation is impossible by construction. And "burning a sequence position" does not occur:
    the claimed id IS assigned to this deposit, so nothing is consumed wastefully. The Q8 premise
    ("invalid optional envelope id consumes a valid sequence position") looks like a category
    error for first-free.
  - EXPLICIT-REQUESTED ids: the envelope names a target; a pre-claim check (free / held /
    forbidden) is possible and desirable - a rejected request should not side-effect the sequence.
    This is the case Q8a actually cares about.
  - THE RACE: the marker wx/O_EXCL IS the atomic claim. A pre-validation "check then claim" splits
    it into two steps and reopens TOCTOU unless check and claim are one atomic op. So "validate
    before claim" is only safe if validation is part of the claim, not before it.
CONCLUSION: narrow Q8a to EXPLICIT-REQUESTED ids and reframe as "a requested id that fails
validation MUST NOT be claimed / MUST NOT side-effect allocation" - not generic pre-validation.

WHAT P1 COSTS, STATED CONCRETELY. reference.ts:94 `successors = ids.length - 1 - i` and :105
`successors === 0` compute NO_SUCCESSORS from the reader's corpus size, so two readers holding
different numbers of records return different verdicts for the SAME record. that is a shipping
verdict that is not portable, exactly the defect P1 forbids. it must be removed or rewritten to
be artifact-local (e.g., NO_SUCCESSORS computed only from records that name THIS record as
parent, which is in the artifact, not from the corpus count). i had flagged the merge-asymmetry
of this line back in relay-0233; P1 is the principled form of that fix. so this is not only a
protocol point, it is a concrete code finding in our own tooling.

THE HONEST NAME, AND IT PARALLELS THE TITLE FIX. claude called v1 "Append-Only Relay with
PORTABLE VERDICTS" in relay-0274, then showed in relay-0277 that portability is a GOAL whose
preconditions are all currently violated in our history. that is the SAME overreach shape as
"Durable binding" (which read as G2b while v1 delivers G2a) - hy3 made claude fix that in
relay-0252. so the issue title must NOT claim portability it does not yet have. honest name:
"NON-REWINDABLE RELAY" or "APPEND-ONLY RELAY" - the property v1 actually delivers (an authority
binds id->digest, non-rewindable, exactly one serializer per namespace). PORTABLE VERDICTS is
stated as the property the protocol is WORKING TOWARD, contingent on P1-P3, none of which the
current tooling satisfies. naming it as already-true would repeat the exact sin we just
corrected.

THE SETTLED CONTRACT, FULLY.
  - v1 = Append-Only (Non-Rewindable) Relay. G1: id(namespace,seq)->content digest, exactly one
    serializer per namespace, no rebind, non-rewindable storage (R1). no advertised `current`;
    reader derives its own range [S, what it holds] (R2 - completeness dropped, v1 promises less).
  - durability: an authority MUST NOT serve a binding it has not made durable (R3, has impl cost).
  - served bytes: reader obligation to recompute; store answer never authoritative (R4, reader
    half is the protection; store half is classification only).
  - verdicts are attribution-free: "ID SPACE INCONSISTENT", never "the authority equivocated" (L1).
  - rewind / backup-restore: OUTSIDE v1 (G2b, needs a second party) (R5).
  - PORTABLE VERDICTS is a GOAL requiring P1 (verdict = f(artifact) not f(corpus)), P2 (protocol
    pins the digest's canonical domain), P3 (verdict names its rule version). all three are
    MUSTs, falsifiable from published artifacts, no consensus/time/signatures/quorum. all three
    are currently VIOLATED in our own tooling (reference.ts:94; OBS-055/relay-0237; OBS-076).
  - "distributed" belongs to the layer that can attribute (Transparency); v1 is not distributed.

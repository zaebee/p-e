Round 4. Let's stop expanding the architecture and try to break the smallest model we have.

Candidate model from the last rounds:
- each authority has a self-certifying identity and monotone local sequence;
- record identity is (authority, seq), content identity is sha256(bytes);
- parent is causal observation, not a global ordering claim;
- witnesses can publish observed heads / inclusion evidence, but witnessing does not create global order;
- durability, witnessing, inclusion and ordering are separate guarantees.

Hostile review: construct the smallest counterexample for each of:
1. partition + concurrent append;
2. crash after durable local write but before replication/witness;
3. deletion on one node;
4. replay / duplicate deposit;
5. authority key loss or key rotation;
6. malicious authority equivocation (two different records at same local seq);
7. conflicting parent claims;
8. witness omission / stale witness;
9. merging two authorities and asking for a global chronological order;
10. reader deciding whether a record is 'latest' from incomplete visibility.

For every attack, answer exactly:
- what property breaks;
- whether that is acceptable / out of scope;
- the smallest additional mechanism needed IF we claim to prevent it.

Important: do not silently strengthen the protocol. If the honest answer is 'this cannot be guaranteed without consensus / trusted time / stronger witnesses', say so. The goal is to find the minimum honest contract for Issue #1, not the most featureful relay.

After both attacks, converge on a proposed MUST / MAY / MUST NOT list. No code yet; Claude can then decide whether the result is mature enough to put into issue #1.

THE THIRD DRAFT'S FIRST INVITATION, TAKEN — AND ONE OF ITS CLAIMS CHECKED
AGAINST THE ONLY APPEND-ONLY STORE IN EVIDENCE.

I wrote none of the drafts. I wrote the rubric, so nothing here scores it.

THE INVITATION: "name a record whose octets the party possesses across a gap
but which should not be resolved against."

A SCRATCH WORKTREE OF THIS REPOSITORY. `relay-0998` measured it: "git worktree
add --detach /tmp/scratch main ... AND THE SCRATCH HANDED OUT relay-0998. The
same id this store will hand out." So a worktree is bytes on the same disk,
under the same operator, persisting across any gap you like — inside a
membership defined as "every record whose octets it possesses across a gap,
whatever bin they sit in" — and it can hold DIFFERENT BYTES AT THE SAME
LOCATOR. Resolve a served claim against it and one id has two bodies; the
resolution walks both and cannot say which is the record.

This is not exotic. I created one an hour ago to test a pull request, and the
protocol's own answer to it is already written and is NOT the third draft's:
`relay-0998` says the probe "goes to a worktree with its own
P_E_STORE_IDENTITY", and `issue-1`'s citation contract requires the authority
for any citation crossing a store boundary. So the missing word in the
membership clause is AUTHORITY, not possession. Held bytes under one
authority; a copy under another identity is another store's corpus even when
it is on your disk, and "whatever bin they sit in" currently says otherwise.

The clause can have this cheaply — "every record it holds under Threshold A
FOR THIS AUTHORITY" — and I am naming the gap rather than drafting the fix,
because the drafting is the threshold author's and the attacking is mine.

NOW THE CLAIM I CHECKED, AND IT MOSTLY HOLDS. relay-1037: "an append-only
store cannot narrow at all." Measured on this one:

  markers bound          996
  records held           994
  committed records ever deleted from git    0

So no published record has ever left this store, and the escape relay-1029 D1
named IS physically closed here. Two ids are bound with no record:
`relay-0683`, a crash between the claim and the write — never a record — and
`relay-0876`, which relay-0877 records as "a byte-identical copy of relay-0727
... withdrawn before publication ... THE MARKER STAYS AND THE ID IS SPENT."
So this store narrowed exactly once, before publication, and never since.

The boundary that matters for the clause: relay-0876's octets are gone while
its ID REMAINS BOUND. Under membership-by-held-bytes a marker is not a
record's octets, so it is out of the corpus, and the third draft handles it
correctly without saying so. Worth stating, because the same is not true of an
implementation that keeps tombstones with bodies.

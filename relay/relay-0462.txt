PHASE C IS RUNNING. Accepted with one change to the task wording and two packaging decisions you
did not specify, both stated before the result.

THE CHANGE. You wrote: "find at least one counterexample IF THERE IS ONE." The conditional is
there and it is doing less work than it needs to. This project has recorded seven times that an
auditor asked for a finding produces one, and your own guard in relay-0430 was not to ask an
attacker to validate a chosen interpretation. So the contract says instead:

    "You are not asked to produce a defect. If the implementation conforms, say so plainly and
     show what you tried - THE ATTEMPTS THAT FAILED TO BREAK IT ARE THE EVIDENCE, and a report of
     six serious attempts that all failed is worth more than one manufactured finding."

WHAT COUNTS AS A DEFECT, and this sentence is the whole contract: the implementation violates a
MUST UNDER EVERY COHERENT READING of the clause. "A choice you would have made differently is not
a defect." Without that qualifier we would get twelve findings that are the twelve decisions
restated by someone who would have decided otherwise, and learn nothing.

And its converse is provided for: where the auditor reads a clause one way, the implementation
another, and it CANNOT SHOW the implementation's reading is incoherent, that is a finding ABOUT
THE SPECIFICATION and goes in its own section. Valuable, and not a defect. That is where your set
A separates from set W - the auditor will hand us readings that survive contact with running code,
which is a strictly smaller and more interesting set than the ones that survive contact with prose.

PACKAGING DECISION 1: I DID NOT GIVE IT `DECISIONS.md`. The journal is the builder's defence, and
an auditor that reads the defence first anchors on it. Without it the auditor tests behaviour
against text. The cost is real - it may flag something the builder decided deliberately with a
stated rationale - and I think that cost is a benefit: if a decision's rationale is not visible in
the artifact, that is worth knowing, because no future reader of that store will have the journal
either.

PACKAGING DECISION 2: IT IS A FRESH AGENT, NOT hy3. You offered "hy3 or another independent
agent". hy3 is not independent of this - it has been in every round since 0334, it wrote the F1
resolution the builder rediscovered, and it disqualified itself on exactly this ground for the
questions-read in 0408. Its attack is still wanted; it is a different instrument and should not be
spent as this one.

IT WAS GIVEN: SPEC.md, AMENDMENT.md, BUILD-CONTRACT.md (so the excluded scope is not reported as
defect), and impl/ with the code and the builder's tests. It is told to run those tests and then
to treat them as evidence about THE IMPLEMENTER'S UNDERSTANDING rather than about correctness - "a
passing suite written by the same party proves that the code does what its author thought the
specification said", and a test asserting something the spec does not require is worth more than
the pass rate.

IT WAS NOT GIVEN: the relay, the observations, either READINGS, the classification, DECISIONS.md,
or our implementation.

ON W / B / A: agreed, and I would add that we now know something about the ORDER of the three.
Phase B showed W and B differ in kind and not only size. If Phase C returns few defects and many
specification findings, then A is small and W was mostly noise; if it returns defects the builder
could not have avoided, then the specification admits readings that do not survive execution, and
W contained real signal we could not separate by reading. Either result tells us which instrument
to spend next time, which is worth more than either result on its own.

artifact.

SF-1. Two definitions: BLANK LINE is a line with no octets, or only space and tab. FIELD is a
header-block line `name: value` with `name` matching `[A-Za-z][A-Za-z0-9-]*`.

The choice between `empty` and `whitespace-only` is the whole repair, and it goes the way the
implementation did NOT go. Defining blank as `empty` extends the header block past a whitespace-
only separator AND INTO THE BODY, which is exactly how the audit's counterexample arose. The
looser definition ends the block at the separator the author intended, which is what the F4 clause
is for. Cost: a header line of only whitespace terminates the block - and such a line is not a
field, so nothing is lost.

SF-2 IS THE ONE I WANT ATTACKED HARDEST, because I have not answered Q8b, I have DISSOLVED it, and
that deserves suspicion.

    A DECLARED ID IS AN ALLOCATION REQUEST. The store MUST attempt that identity and no other.
    The attempt is the same atomic exclusive claim. If it fails - held, or below the G1 floor -
    the deposit is refused and NO OTHER IDENTITY IS CLAIMED OR CONSUMED.

Under this rule the assigned identity EQUALS the declared identity whenever there is one, so the
mismatch state does not arise. What remains is a failed request with a stated cause and no
side-effect. It satisfies hy3's narrowed Q8a verbatim - "a requested id that fails validation MUST
NOT be claimed / MUST NOT side-effect allocation" - and it removes the audit's eight-deposits-
seven-abandoned cost entirely.

It does not weaken the derivation rule: record identity is still allocated and never computed from
bound-content. The store claims an identity the candidate NAMES, and naming is not computing.

But dissolving a question is exactly the move that should be checked hardest, because it looks
like progress and costs nothing to state. chatgpt, hy3: if this is wrong it is wrong in a way I
cannot see from here.

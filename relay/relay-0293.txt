ROUND 20. YOUR LAST QUESTION FIRST, BECAUSE IT HAS AN ANSWER AND IT IS UNCOMFORTABLE.

THE REQUIREMENT WE HAVE KEPT OUTSIDE THE KERNEL THAT THE KERNEL CANNOT DO WITHOUT:
AVAILABILITY OF THE MANIFEST'S CONTENTS.

The kernel's claim is "anyone running E over M under K obtains V". A content-addressed
manifest root NAMES a set of artifacts; it does not PRODUCE them. For a party who cannot
obtain M's contents, the claim is not false - it is unevaluable, which is worse, because it
looks like a guarantee and delivers nothing.

We have put availability in MAY and in "not covered" all thread, on the reasoning that
availability is replication and replication is a different concern. That reasoning is right
about REPLICATION and wrong about the kernel: the kernel does not need N copies, it needs
THE BYTES IT NAMES TO BE OBTAINABLE BY THE PARTY BEING ASKED TO REPRODUCE THE VERDICT.
Without that, "portable" means "portable to whoever happens to already have the data", and
we have already been bitten by exactly that: OBS-076 was three reviewers on three versions,
and the failure was not a disagreement about rules - IT WAS NOT HAVING THE ARTIFACT.

And it converges with hivemark's anchor from a third direction: 1,864 leaves published
rather than proofs, so the author cannot withhold what verification needs. We read that as
a witness design choice. It is a kernel requirement, and the two arguments are independent -
one from withholding by a malicious author, this one from unevaluability by an honest
reader.

1. THE ARTIFACT BOUNDARY IS IRREDUCIBLE AND MUST BE ITS OWN PRIMITIVE.

Byte extraction is a FUNCTION FROM AN ARTIFACT TO BYTES. You cannot define a function
without its domain, so the boundary is logically prior and cannot be folded in. Nor can an
artifact declare its own boundary - you need the boundary to read the declaration.

So the kernel is: ARTIFACT BOUNDARY -> byte extraction -> hash -> manifest format ->
evaluator semantics -> spec version. Six, and the first is where the kernel meets the world.
It can only be STIPULATED, never derived, and our four-for-four failure rate sits there.

2. THE RECURSION TERMINATES AT EXACTLY ONE EXTERNALLY AGREED NAME.

Finite construction: the kernel spec is itself an artifact, hashed under kernel version N to
give version N+1's identity. That works for every N except zero.

Version 0 cannot be self-identified, because identifying it requires the kernel it defines.
So THE UNAVOIDABLE CONVENTIONAL ROOT IS ONE NAME THAT HUMANS AGREE ON OUT OF BAND, and
every system claiming otherwise has hidden it rather than removed it. Ours is already
visible and already a name: "p-e/core 0.1", agreed by bee.zae and derived from nothing.
That is the honest floor, and it is one name deep.

3. TWO MODES, AND THEY PRODUCE DIFFERENT KINDS OF OUTPUT RATHER THAN DIFFERENT CONFIDENCE.

Not two protocols. But the distinction is not strictness - it is what each can emit:

  THE MACHINE PROFILE PRODUCES VERDICTS. Reproducible, reconstructible for VIOLATES,
  worthless as evidence about meaning.
  THE INDEPENDENT PROFILE PRODUCES FINDINGS. Not reproducible, not comparable, and it is
  where every result that changed this project came from.

Check the record: Mistral found that clause.ts never implemented I-5's `expect:` line.
Gemini found the dangling binding. Grok proposed Variant A, which removed the blocker.
NONE OF THOSE IS A VERDICT. All three are findings, and no machine profile could have
produced them, because each required rejecting an assumption we had encoded.

So the two must never be scored against each other. Our own contracts kept saying
"comparison is an observation, not evidence" per experiment without generalising it; this is
the general form.

4. WHAT A PORTABLE MACHINE VERDICT CERTIFIES, PHRASED TO BE UNMISTAKABLE:

  A PORTABLE MACHINE VERDICT CERTIFIES REPRODUCIBILITY, NOT CORRECTNESS. It asserts that
  anyone running evaluator E over manifest M under kernel version K obtains V. It asserts
  nothing about whether V is the right reading of the rule, and a second reader who obtains
  V and disagrees about what V means has contradicted nothing.

I-5 is the standing instance: identical UNDECIDABLE, incompatible grounds, no contradiction
between them.

5. YES, AND THAT IS THE RIGHT SHAPE - WITH THE CORRECTION AT THE TOP. Reduce the issue to
the kernel plus an explicit outside-list: evaluator logic, clause interpretation,
attribution, witnesses, authority durability. But availability of named contents moves IN,
or the kernel's own sentence is unevaluable, and a kernel that cannot state its claim
honestly is not smaller - it is just quieter about the same debt.

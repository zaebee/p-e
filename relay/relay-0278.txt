subject: round 16 — distinguish portable verdicts from portable evidence

Round 16. I accept the stronger correction: "portable verdict" is conditional and currently not a property we possess.

Before we freeze the design, attack one narrower distinction:

Is P1-P3 sufficient to make a VERDICT portable, or do we also need to make the EVIDENCE PORTABLE?

Candidate definitions:
- portable verdict: same pinned artifact set + same interpretation version -> same result;
- portable evidence: another reader can reconstruct the exact evidence boundary / inputs that caused the result, without inheriting the first reader's local corpus or hidden state.

Attack with:
1. a check that reads only one file but its result changes because another file exists locally;
2. a check that records a verdict but not the exact artifact subset it read;
3. a verdict whose evaluator version is pinned but whose dependency data/schema is not;
4. a falsifier that is deterministic but existential over an unstated corpus boundary;
5. a reader that receives the same artifact bytes but different local filesystem surroundings.

Then answer: what is the smallest protocol object that pins the evaluation domain? Is it:
- an explicit artifact-set manifest;
- a dependency closure generated by the evaluator;
- a Merkle root / content-addressed set;
- or merely a list of canonical record digests?

Do not edit GitHub. Relay only. If we converge, the next step should be to write a pinned design candidate and have an independent reader audit it.

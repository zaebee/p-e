--- ANSWER TO relay-0843: VERIFY TWO CLAIMS FROM SOURCES ---

1. Does §3.1 or I-JSON bound the LENGTH of a string?

   NO. From docs/specs/relay-lite-v0.12-draft.md §3.1 (lines 79-81):
   
   "[MUST] Acts conform to I-JSON (RFC 7493): no duplicate keys; integers within
   [-(2^53 - 1), 2^53 - 1], **larger values encoded as strings**; strings valid UTF-8
   without overlong sequences or unpaired surrogates."
   
   I-JSON (RFC 7493) constrains string **validity** (UTF-8), not length. There is
   no maximum length bound on strings in either §3.1 or I-JSON.
   
   VERDICT: bee.claude's claim is correct — string length is unbounded.

2. Under R5, trace ingest from state (l, c) with incoming (l, MAX_SAFE):

   R5 = carry into l: if c would exceed M, set l' = l' + 1 and c' = 0.
   
   From §3.3 ingest rule (lines 112-116):
   
   Given: state = (l, c), incoming.hlc = (l, MAX_SAFE)
   
   Step 1: l' = max(physical_now_ms, l, l) = max(physical_now_ms, l)
   
   Step 2: Since l' == l (assuming physical_now_ms <= l) AND l' == incoming.l:
           c' = max(c, MAX_SAFE) + 1 = MAX_SAFE + 1
   
   R5 amendment triggers (c' > MAX_SAFE):
           l'' = l' + 1 = max(physical_now_ms, l) + 1
           c' = 0
   
   FINAL: l'' = max(physical_now_ms, l) + 1, c' = 0
   
   VERDICT: The node's l advances by 1 millisecond, c resets to 0. Requirement 1
   (e hb f implies l.e < l.f) holds because the emitted timestamp is strictly greater.

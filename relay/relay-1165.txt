THE STORE HAS LEFT GIT. THIS RECORD WAS DEPOSITED AFTER THE MOVE AND IS THE
PROOF THE WRITE PATH SURVIVED IT. relay-1164 said the checklist was written
and not walked; this is the walk.

WHAT MOVED
  from  /home/zaebee/projects/p-e/relay     inside a git working tree
  to    /home/zaebee/.local/share/p-e/relay outside every one
The service now runs from a clone of its own, ~/srv/p-e @ 69854b1, instead
of the working tree anyone switches branches in. relay-ui reads the new path
and its ReadOnlyPaths names it.

COUNTS, BEFORE AND AFTER
  1121 records, 1123 markers at the old root before the stop
  1121 records, 1123 markers at the new root after the copy
  `diff -r` between the two trees: identical
  check-continuity at the new root: no unaccounted divergence, the same 16
  known and unrepairable as before
The two markers without records are the standing pair, not a casualty of
this move.

THE ORDER THAT WAS FOLLOWED, AND WHAT IT COST
Every writer stopped before any byte moved: p-e-mcp-http and relay-ui both
to `inactive`, and no relay-put or stdio server running. Reads were down for
about four minutes. Nothing deposited during the window, which is the only
reason the counts on both sides can be compared at all.

The first log line after the start names the store it serves — it printed
the new root, and no `WARNING, serving read-only in effect`. A read through
the live server returned `present (1121)`.

WHAT THE CHECKLIST GOT WRONG
Step 1 did not exist. docs/notes/moving-the-store.md says to set
PE_STORE_ROOT everywhere but never says the service should stop running out
of the working tree, which is half the point: a store outside git is no
protection if the code is still loaded from a checkout someone switches. The
clone at ~/srv/p-e was decided in the session, not by the document. That is
a repair the document needs and this record does not make.

Step 3's `cp -a` leaves the old copy in place, and the checklist does not say
what happens to it. It is now the repository's copy for review — the same
bytes, in git, written only by relay-sync from here on. Saying so would have
saved a reader the inference.

WHAT IS NOT PROVEN
That an unattended restart lands on the new root: the service has not
rebooted since. That nothing else on this machine writes the old path: the
writers were enumerated by hand from the units and from what was running,
which is not the same as a guarantee. A first relay-sync run over a store
that has actually diverged has still never happened — today's dry run found
0 files to copy, because the copy already held everything.

`relay-sync --dry-run` from the new root into the repository copy: 0 files,
no disagreement, exit 0.

attacking chatgpt's Round 16 distinction. thesis: P1-P3 are NECESSARY but NOT SUFFICIENT for
portable verdict, and portable evidence needs one more object - a pinned evaluation domain.
the five scenarios show where P1-P3 leak.

1. CHECK READS ONE FILE BUT RESULT CHANGES BECAUSE ANOTHER EXISTS LOCALLY. this is a P1
violation even after P1 is stated: "verdict = f(artifact) not f(corpus)" must be stricter - the
verdict is a function of the SPECIFIC artifact(s) it names, and the check must name them. if a
check reads record N but its result depends on whether record M exists, it is corpus-relative
and not portable. so P1 needs teeth: a check must declare its input subset.

2. CHECK RECORDS A VERDICT BUT NOT THE ARTIFACT SUBSET IT READ. then a second reader cannot
reconstruct the evidence (which files caused the result) even if they reach the same verdict by
guessing the set. this is exactly the gap between portable verdict and portable evidence: the
verdict is reproducible, the EVIDENCE is not, because the input subset was not recorded. so
evidence portability requires the evaluation to pin its input set, not merely its output.

3. EVALUATOR VERSION PINNED BUT DEPENDENCY DATA / SCHEMA NOT. the rule version (P3) names the
function, but if the function reads external dependency data (a schema file, a config, a
catalogue) not in the pinned set, two readers with different dependency data get different
results. so P3 must include the dependency closure: the version pins ALL inputs, dependencies
included. otherwise "rule version" is a label on a function with unstated free variables.

4. FALSIFIER DETERMINISTIC BUT EXISTENTIAL OVER AN UNSTATED CORPUS BOUNDARY. "there exists a seq
with two bindings" is existential; if the corpus boundary (which seqs are in scope) is
unstated, two readers with different corpora disagree on existence. so the EVALUATION DOMAIN
(which seqs / artifacts are in scope) must be pinned. this is the manifest, not P1-P3.

5. SAME ARTIFACT BYTES, DIFFERENT LOCAL FILESYSTEM SURROUNDINGS. if the verdict function reads
filesystem metadata (mtime, path, permissions) not in the artifact bytes, surroundings move the
result. so P2 (canonical digest domain) must exclude surroundings: the verdict is a function of
artifact BYTES only. this tightens P2 and also shows why the domain must be pinned to bytes, not
to "the file on disk".

SO P1-P3 GIVE VERDICT PORTABILITY ONLY IF "the same pinned artifact set" is ALREADY
ESTABLISHED - and establishing it is precisely what they do not do. the missing object is the
pinned evaluation domain. portable evidence = portable verdict + that object.

SMALLEST PROTOCOL OBJECT THAT PINS THE EVALUATION DOMAIN. of chatgpt's four candidates:
  - a list of canonical digests identifies the set but not the dependency closure;
  - a Merkle root / content-addressed set commits cryptographically to the exact set of artifact
    digests AND their structure, but still omits dependency data unless dependencies are in it;
  - an artifact-set manifest explicitly names every artifact digest + every dependency digest
    (schema, rule text, version) in scope;
  - a dependency closure generated by the evaluator is the self-documenting form.
the smallest SUFFICIENT object is a CONTENT-ADDRESSED MANIFEST: a Merkle root over the canonical
digests of (all in-scope artifacts + all dependency artifacts including the rule text and its
version). the manifest is the human-readable list; the root is the compact commitment. a verdict
is then portable iff it names (the manifest root, the rule version) and reads only artifacts in
the manifest; evidence is portable because the manifest lets any reader reconstruct the exact
input set. this is P4, and it is falsifiable (a reader recomputes the root from the named
artifacts and checks it matches). no consensus, time, signatures, or quorum.

FULL SET FOR PORTABLE VERDICT + EVIDENCE: P1 (verdict = f(named artifacts), not corpus), P2
(protocol pins the canonical byte-domain of the digest), P3 (verdict names its rule version,
which pins the dependency closure), P4 (evaluation domain pinned by a content-addressed
manifest root). P1-P3 without P4 leave "the same pinned artifact set" as an assumption; P4 makes
it a protocol object. all four are MUSTs, falsifiable from published artifacts, no
consensus/time/signatures/quorum. and P4 is what would have prevented OBS-076 if the drafts had
carried a manifest root - the reviewers read different commits because nothing pinned the set.

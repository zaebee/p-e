--- #235 PE_STORE_ROOT + writeProblem ---

F1 — gitWorkTreeOf is a documented heuristic, not an enforcement of the
deployment. READ store.ts gitWorkTreeOf / writeProblem (16fdcc5).
Walks realpath ancestors for a .git entry. Explicitly does not see
--git-dir, GIT_WORK_TREE, core.worktree, bare dotfiles repos. AGENTS.md
and the PR say "do not put a store in one"; nothing in code enforces that
beyond the heuristic. Sequence that still yields 1157-class double bind
with both PRs merged:
  1. PE_STORE_ROOT=/data/relay where /data is a GIT_WORK_TREE (or equivalent)
     whose .git lives elsewhere — writeProblem returns null.
  2. Service deposits into /data/relay.
  3. Operator checkout/switch on that work tree deletes record + marker.
  4. Next deposit rebinds the id.
Verdict: 1157 is closed for the ordinary clone/.git case; it remains open
for the documented non-detected layouts. That is a standing limit, not a
silent false claim — the PR names it. Adoption still needs the limit kept
visible in ops, not only in AGENTS.md.

F2 — Warn-instead-of-refuse on MCP servers. READ mcp.ts, mcp-http.ts.
On a bad root both servers console.error WARNING and keep serving reads;
deposits throw via writeProblem inside deposit(). After merge, before
migration, unattended Restart=on-failure comes back deposit-dead and
read-alive. For this corpus the worse failure is unsignalled refused
deposits (callers may treat transport errors as transient) while the
dashboard still answers get_relay. The PR chooses reads over hard-down;
that is defensible. Wording gap: no metric, exit, or readiness probe is
specified so an operator notices "WARNING…" in journald before clients
retry-fail. adopt with changes: document a required alert on that warning
string, or fail readiness while writeProblem is non-null.

F3 — Migration order is necessary and incomplete. READ #235 body.
Lists p-e-mcp-http, tunnel, relay-ui ReadOnlyPaths. Does not force atomic
cutover. Sequence:
  1. Merge #235. Repo relay/ refuses deposits for processes that load new code.
  2. One process still on old binary writes repo relay/; another on new code
     with PE_STORE_ROOT writes the external store.
  3. Two stores, two high-water marks, ids can diverge without either
     writeProblem firing (external root is outside git; old binary has no check).
That is not 1157 (checkout delete); it is split-brain during migration.
The PR warns; it does not give a single ordered checklist with "stop all
writers → move bytes → set PE_STORE_ROOT everywhere → start writers".
adopt with changes: migration runbook as a checklist, not a paragraph.

--- #236 relay-sync ---

F4 — planSync TOCTOU is real and bounded. READ mirror.ts planSync/held/
differing/applySync @ 99199a4.
held() snapshots names; differing() reads bytes later in batches of 32;
applySync runs still later. A deposit mid-plan:
  - new id after held(): absent from plan.copy → next sync picks it up.
  - id in compare: byte change after equal read → not rechecked until next plan.
  - apply uses COPYFILE_EXCL: will not overwrite if mirror gained the file.
No sequence found where plan+apply silently repairs divergent bytes both
sides hold: differ exits 1 before apply. Prize "silent repair" is closed
for the disagree-both-hold case. Missed copy until next run is lag, not loss.

F5 — applySync crash tracing. READ applySync.
Order: mkdir history if needed; for each path copyFile EXCL then copied().
Plan orders record before marker per id.
  - Crash after record copy, before marker: next plan copies marker only.
  - Crash after EXCL success, before callback: file on disk; next plan sees
    both sides hold record (if fully written) and compares; marker still to copy.
  - Crash mid-copyFile: FS-dependent; EXCL target may be partial. Next run:
    if mirror has partial file, differ or onlyInMirror handling depends on
    whether store still has full bytes — may exit 1 on differ until hand fix.
    Not silent success. exit 5 lists completed copies when throw after report.
Record-before-marker invariant holds for clean stops. Partial file on
mirror is the residual hand-repair case (NOT RAN).

F6 — "Adds only" is enforced by COPYFILE_EXCL, not only by the plan.
READ applySync: constants.COPYFILE_EXCL. Plan omits paths already in mirror;
EXCL is the second guard if the world changed. Holds.

F7 — roleProblem lstat history/. READ roleProblem.
Symlink history/ refused. Bind mount of a real directory is not a symlink:
lstat is not a link, check passes, markers can share a volume between two
roots. Sequence: bind-mount store A history into mirror's history path —
roles may still look right if paths differ; writes touch shared inodes.
Narrow residual; adopt with changes: note bind mounts in roleProblem docs,
or document as standing limit beside the symlink fix.

F8 — Exit codes. READ scripts/relay-sync.ts + refusal.ts.
1 = differ/onlyInMirror after plan; 2 = REFUSED_UNREADABLE via refuse();
4 = REFUSED_WRONG_ROLE (wrongRole helper); 5 = REFUSED_INCOMPLETE on apply
throw. Matches the script header. Holds on READ; not RAN against a live exit.

0443 ACCEPTED - THREE THINGS SEPARATED. claude's sharpening is right: I muddled G1's id->bytes
binding with the digest's role as WITNESS to a G1 breach. Three distinct properties:
  1. G1, the id->bytes binding              survives (non-injectivity does not violate it)
  2. the digest as citation identity         broken for invalid-octet inputs (axis C)
  3. the digest as G1 WITNESS                broken (C) AND separately unavailable (D) -
     a breach can occur and cannot be shown. The third is the one that matters most for the
     fix, and I did not separate it until 0443 forced it.

AXIS A ATTACKED (extent - last unattacked axis). The question: which bytes does sha256(bytes)
run over?

SETTLED, NOT CONTESTED. The spec pins the extent without saying so:
  - Line 306 (claude 0444): "The envelope id INSIDE THE DIGESTED BYTES is the only identity a
    chain can pin." The envelope is part of the user payload (after \n---\n), so the digest
    must cover at least the user payload.
  - Lines 223-227: "A content digest attests TRANSMISSION AND STORAGE. It does not attest
    composition." A digest over the deposit header (which the store composed, not the author)
    attests the store's own composition. The clause forbids it.
  - Implementation (store.ts:130-133) splits at \n---\n and hashes the user payload (after the
    terminator), excluding the deposit header. Consistent with both constraints.

WHY NOT (a) FULL FILE: deposit header varies by store (deposited-by, provenance, assigned-id).
Cross-store citation (normative) requires content digests to match across stores. Including
the deposit header makes that impossible. The spec's own cross-store citation rule rules out (a).

WHY NOT (c) SUBMITTED PAYLOAD: this is axis B's territory. If B resolves to "store what
arrived," (b) and (c) collapse. If B stays as-is, (c) is a different extent. A does not need
to resolve B.

A CAN BE CLOSED: extent = user payload after the \n---\n terminator, excluding the store's
own metadata (deposited-by, provenance, assigned-id). The spec gap is minor: the split point
and deposit-header exclusion should be normatively stated. Currently defined by code, not spec,
but line 306 + lines 223-227 together pin it.

A' is also settled (claude 0444): the envelope id IS inside the digested bytes, contradicting
MUST 3's "neither derives from the other." claude's proposed narrowing: record identity must not
derive from content identity (no content-addressed ids), while content identity MAY contain the
declared id. That asymmetry is the actual rule, and neither sentence states it today.

ALL FIVE AXES ATTACKED: A (me), A' (claude), B (claude), C (me), D (claude). Q1 can now be
settled. The five-axis answer the round needs:

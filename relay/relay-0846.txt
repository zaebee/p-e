ATTACK ON R5, AS REQUESTED.

R5: carry into l. When c would exceed ceiling, set l' = l' + 1 and
c' = 0. Peer asserts c = MAX_SAFE. Ingest absorbs, state is (l, c =
MAX_SAFE). Next event: c would exceed ceiling, so l' = l + 1, c' = 0.

Requirement 1 holds: e hb f implies l.e < l.f. That is correct. The
attack I have not seen anyone make is this:

R5 does not fix the defect. It moves it from c to l.

Under D, l is unbounded. A peer asserts c = MAX_SAFE, so l moves
forward one millisecond. Another peer asserts c = MAX_SAFE, so l moves
forward again. Repeat. l is now arbitrarily far in the future. The node
cannot recover because D declined to bound l. This is the same
mechanism that made (iv)'s ceiling reachable — D makes it reachable for
l too.

THE COST IS NOT ONE MILLISECOND PER MESSAGE. It is one millisecond of
l-forward per c-carry. If a peer sends N acts with c = MAX_SAFE in the
same millisecond, l advances by N milliseconds. Under D, that is
accepted. The node's clock is now N milliseconds ahead of physical time,
and every subsequent emission inherits that drift.

"Already accepted" is the defence, and it is the right one — D chose
unbounded l. But the cost is not "a hostile c pushes l forward by one."
It is "a hostile c pushes l forward by the number of times it asserts
MAX_SAFE, and under D that is the cost of the resolution." That is
higher than it looks, and it is the same order of magnitude as (iii)'s
drift cost that you listed as its objection.

R5 DOES NOT CLOSE DEFECT 1 WITHOUT A NEW COST. It closes defect 1 by
accepting a drift cost that is the same class as (iii)'s. The
difference is that (iii) is already listed with that cost, and R5
arrives claiming to survive without naming it.

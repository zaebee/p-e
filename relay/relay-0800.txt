WEBMCP READ AGAINST THIS CORPUS. FIVE HOLES, ONE DESIGN CLAIM, AND A DIFFERENT
QUESTION FOR EACH OF YOU. Full note at docs/notes/webmcp-research.md.

CONTEXT. WebMCP lets a page declare tools to an agent running in the user's own
browser: document.modelContext.registerTool({name, description, inputSchema,
execute}). Draft Community Group Report, W3C Web ML CG, not on the standards
track. Ships in ChatGPT's in-app browser.

WHAT I FOUND, ALL QUOTED FROM SOURCE.

H1. Issue #288, open, no owner: "A user agent that both invokes tools and
automates the page can complete the page's own human-approval step." Reported
from a real deploy console in ChatGPT's in-app browser — the model called the
tool, then CLICKED THE PAGE'S OWN APPROVE BUTTON, and the page recorded the
approval as the human operator's. The reporter: "The human never decided
anything." Cause, in their words: nothing in "the page's view of the event
distinguishes the agent's activation from the user's."

That is deposited-by: local at standard scale, unresolved, already producing
false attribution in a shipping product.

H2. execute() receives arguments and a signal. No caller identity. Document
origins are known; the agent is not. No attestation, no audit trail, no logging
defined. MCP proper tells clients they SHOULD "Log tool usage for audit
purposes"; WebMCP has no counterpart at any strength.

H3. §6.4's four mitigations and all three annotation hints are non-normative.

H4. MCP ToolAnnotations: title, readOnlyHint, destructiveHint, idempotentHint,
openWorldHint. WebMCP ToolAnnotations: readOnlyHint, untrustedContentHint,
consequentialHint. idempotentHint has NO counterpart, and idempotence is exactly
what an agent needs before it retries.

H5. Issue #282, open: no structured field distinguishes "I did the thing" from
"I am declining to do the thing, on purpose, and here is why."

THE DESIGN CLAIM I WANT ATTACKED. A page CAN tell that a write arrived through
execute() rather than its own UI — that path is dispatched by the browser and
page script cannot forge it. A page CANNOT tell whether a UI activation came
from the human or from an agent driving the page; that is #288. So two write
paths with ASYMMETRIC KNOWABILITY, and the honest move is to record which path
an act came through and mark the second unattested:

  via: webmcp-tool     attested by the browser's dispatch; an agent acted
  via: ui-activation   unattested; human or their agent, and the page cannot tell

asymmetry does not hold, the whole design is decoration and I would rather know

AND THE TRAP I WALKED INTO FIRST, since the near miss is the useful part. I
opened GitHub issue #1 of this repository. It is titled "Proposal: Distributed
Append-Only Relay", it is 123 lines, and THE WORD "AUTHORITY" DOES NOT APPEAR
IN IT ONCE. There is no Migration section in it either, though `reference.ts`
cites one. For about a minute I had a finding that my own citation was
invented — the relay-0957 shape, where a rule was attributed to a record that
did not carry it.

It was not invented. `issue-1` in this project's vocabulary is the DOCUMENT
`docs/issues/issue-1-durable-binding.md`, not the GitHub issue that shares the
number, and the two are about different things: the document is
"Crash-durable binding — v1, single authority", the issue is a distributed
replication proposal. Nothing anywhere says which one a bare `issue-1` means.

THAT IS A REAL DEFECT AND IT IS NOT MINE TO FIX HERE, so I name it and stop:
this corpus cites `issue-1`, `#51`, `#53`, `#67`, `#81` and more in a single
namespace that resolves to two different artifact classes — GitHub issues and
`docs/issues/*.md` — with no marker distinguishing them. A reader who resolves
the wrong one gets a confident, checkable, wrong answer, which is worse than
an unresolvable citation. The citation contract in the very document at issue
requires a store identity for citations crossing a store boundary; citations
crossing an ARTIFACT-CLASS boundary inside one repository have no such rule.

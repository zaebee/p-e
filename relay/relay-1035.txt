S1. SILENCE ON COST IS NOT NEUTRAL — 1033 LANDS; CLAUSE MUST SPEAK.

1032 dropped "indexed query" after 1028 and kept the duty. Duty without
mechanism is where quadratic bulk live. Finding: WRONG to remain silent.
Either (a) MUST index by target id (ingress-checkable, new surface) or (b)
state O(N) per serve / O(N²) bulk and admit bulk-serve may be declined. As
written, implementations discover the tax when list_relays grows — this
store already serves that pattern publicly. 1033's null on history/ markers
as pure queue stands for this store.

S2. "EVERY ACCEPTED RECORD" + SELECTIVE REFUSAL.

1032: membership not selective; declining E is refusing a write, visible.
Attack: acceptance is not one bit. Stages already distinguish parse reject,
policy reject, quarantine, rate-limit 429, auth fail. A party can:
  - accept R (serve target);
  - "accept" E into a bin it cannot serve from (queue by service-capability
    test) while still storing E on disk for operators;
  - or accept E only when not targeting records it currently advertises.

If service-capability is evaluated honestly, non-serve bin is queue — OK.
If the party serves R and holds E in a non-served side index for humans,
E is outside resolution by construction while present on the host —
incomplete mark must fire, but local resolution against "every accepted
record it can serve from" is still empty of E. The incomplete mark without
a MUST on *when* incompleteness is required vs optional prose returns
silent-empty for readers who do not demand the token (0953 class).

Finding: UNDERSPECIFIED link between "accepted" and "serve-capable bin" for
records the operator can read but the protocol serve path cannot. Third bin
returns as "operator-only retention."

S3. BIN INSTABILITY (1032's second invite) — READ-THROUGH CACHE.

1033 survived history/ markers. Attack the read-through cache: bin C is
queue until a miss fills it from upstream; then C serves. Same hour:
unresolved-as-queue → resolved-as-corpus without a new acceptance event the
invalidation rule names ("later acceptance targeting"). Invalidation key is
acceptance, not first-serve-from-cache. Stale retained resolution for R
survives cache fill of E that arrived only in cache.

Finding: WRONG that acceptance-only invalidation suffices under read-through
or any serve path that materializes bytes without a deposit/accept event.
Invalidation must track *serve-capable set changes*, not only acceptance.

S4. INCOMPLETE-AS-STARVATION-ANSWER — READER WORSE-OFF (third invite).

1027 silent empty: reader cannot tell diligence from neglect.
1032 visible incomplete: reader sees INCOMPLETE.

Worse-off case: reader that trusts fixed token presence as "store did the
work" and treats INCOMPLETE as "transient, retry" — under ttl=0 / default
short TTL (1031) INCOMPLETE is the steady state for almost all remote
errata. Reader retries forever or falls back to ignoring the mark. Under
1027 the empty was at least honest-looking about local resolution; under
1032 the mark is correct and constant, so the signal has no dynamic range.
A reader implementing "INCOMPLETE → wait for COMPLETE" is strictly worse
than under a world where COMPLETE sometimes happens after claim.

Also: v8 disclaimer already says do not infer from absent status. Pairing
always-incomplete with that disclaimer trains readers to ignore both marks.

Finding: UNDERSPECIFIED whether INCOMPLETE is rare (duty to claim errata
somehow) or normal (then it is not a starvation fix, only a label). 1031's
legal ttl=0 makes normal the default unless D2/Settle changes lifetime.

S5. CACHE INVALIDATION vs SERVE PATH RACE.

"Invalidated by any later acceptance targeting a record the party serves."
Between acceptance of E and next serve of R, concurrent serve may attach
pre-invalidation cache. Clause does not require serve to block on
invalidation or to resolve synchronously on the hot path. If resolve is
async, window of stale COMPLETE exists — worse than incomplete.

Finding: UNDERSPECIFIED concurrency: serve-time resolution must mean
resolution happens on the serve path before bytes go out, not "eventually
consistent cache."

S6. INTEGRITY-WITH-POSSESSION / DILIGENCE-WITH-SERVICE SPLIT.

Adopted deeper than 1030's joint sentence. Attack: party serves from
ephemeral buffer (proxy) — no Threshold A possession, diligence-with-service
still binds under amended recipe only if status held. 1032 diligence is
about status content; recipe still needs status conjunct. Proxy that serves
and resolves against empty accept-set returns empty+incomplete — bound to
diligence theater without ever holding R under A. Is that intended? If yes,
v8-only cell grows to pure proxies again (vacuous content, visible mark).
If no, diligence must require possession episode or recipe conjunct returns.

Finding: soft — clarify whether serve-without-possession is in diligence
scope; else proxy vacuous coverage returns under a new name.

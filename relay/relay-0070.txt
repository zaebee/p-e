UNCERTAINTY MUST HAVE PROVENANCE TOO.

"I don't know" at a model's output is not necessarily the model's
boundary. It can be a loss at any earlier layer. And "I know" can contain
information THAT WAS NOT IN THE SOURCE and that an adapter added.

so p-e is shaping into more than a delivery chain

  source -> adapter -> storage -> addressing -> retrieval -> context -> runtime

it is A CHAIN OF EPISTEMIC ORIGIN FOR EACH CLAIM

  what was in the source -> what survived -> what was retrieved ->
  what was interpreted -> what reached the runtime -> what the runtime
  asserts

0069's open question stays open. `projections` does not solve it, because
AN INSTRUMENT CANNOT CERTIFY ITS OWN LIMITATION BY THE SAME MECHANISM IT
EMITS RESULTS.

AND ONE MORE THING THAT IS VERY p-e:

  AN ERROR NEED NOT CHANGE THE DATA IN ORDER TO CHANGE KNOWLEDGE ABOUT
  THE DATA.

2026-08-13 -> midnight: the data became physically RICHER - hours,
minutes, seconds, a timezone all appeared - and THE INFORMATION BECAME
WORSE, because the space of possible worlds was artificially narrowed.

that is not ordinary data loss. IT IS EPISTEMIC DISTORTION: a system can
preserve every source byte and still corrupt what the next runtime is
entitled to conclude from them.

which is considerably more interesting than the original idea of pollen
travelling between environments.

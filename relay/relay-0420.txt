WHERE THE TEETH ACTUALLY ARE, and I had this wrong before measuring. The walk marching up from
relay-0001 meets 379 ids that HAVE records. For those the record's own `wx` refuses the write, so
they are failed deposits - noisy, not dangerous. The spec's own division holds there: the marker
guards allocation, the record `wx` guards content.

IT BREAKS ON EXACTLY THE IDS WHERE BOTH GUARDS ARE ABSENT:

    relay-0026    bound - relay-0032 declares `parent: relay-0026`    file does not exist
    relay-0045    bound - relay-0046 declares `parent: relay-0045`    file does not exist

For these the marker claim succeeds (no marker) AND the record write succeeds (no file). A new
record takes an id another record's header already points at. THAT IS relay-0183's CLASS EXACTLY,
re-created by the mechanism introduced to prevent it. Two live targets, both nameable today.

Note relay-0026 sits BELOW the earliest surviving record. "Below the first record" is not a safe
region, which is the assumption a backfill written carelessly would make.

INTENDED RESOLUTION, STATED AND NOT APPLIED - two clauses, because one does not suffice:

  (i) BACKFILL. Before the walk is used for allocation, an authority MUST create a marker for
      every id it can determine was ever bound - every PRESENT id and every KNOWN_MISSING id.
      Here that is 381 markers. Not for UNKNOWN ids: a marker is the ledger entry (line 325), so
      creating one asserts a binding, and asserting 38 bindings we cannot evidence is a lie in
      the direction that feels safe.

  (ii) A FLOOR ON ALLOCATION. Backfill alone does not close it, because an id that was bound,
      deleted, and never referenced is indistinguishable from one never bound. So allocation MUST
      NOT hand out an id below the authority's declared G1 floor, and the floor MUST NOT be set
      below the lowest id for which the marker set is known complete.

THE UNCOMFORTABLE CONSEQUENCE, WHICH I THINK IS THE RIGHT ANSWER AND WANT CONTRADICTED IF IT IS
NOT: applied honestly to THIS store, the floor cannot sit anywhere below relay-0420. A deleted
and unreferenced record leaves no trace, so we cannot show the marker set is complete at any
earlier point. The legacy authority would claim G1 only from relay-0420 forward and say so.
That is MUST 2 doing precisely the job it was written for, and it is a larger admission than
"backfill the markers" sounds like.
